# 第 7 天 - 前后端分离启动任务

## 今日目标

第 7 天正式开始前后端分离，但不一次性拆掉旧系统。目标是：

1. 队长确认基线、接口、旧页面和联调规则。
2. B 同学启动独立前端工程，优先做一个能调后端的样板页。
3. C 同学保持后端 API 稳定，继续保证旧 Thymeleaf 页面可演示。

## B 同学具体任务

| 优先级 | 任务 | 具体要求 | 验收方式 |
| --- | --- | --- | --- |
| P0 | 准备前端工程 | 在 `frontend/` 下建立基础工程；配置本地启动命令；默认后端地址指向 `http://localhost:8080` | 能启动前端首页或样板页 |
| P0 | 建立请求封装 | 封装 `GET`、`POST`、`DELETE` 请求；统一处理 JSON、HTTP 错误和后端 `{ "message": "..." }` 错误 | 页面不要到处重复写 `fetch` 细节 |
| P0 | 迁移学生列表样板页 | 新建学生管理页面；调用 `GET /api/students`；展示 `studentNo`、`name`、`className` | 页面刷新后能看到后端学生数据 |
| P0 | 做页面状态 | 加载中、空数据、请求失败都要有明确状态 | 断开后端时页面能显示失败提示 |
| P1 | 规划前端路由 | 按旧页面映射 `/login`、`/students`、`/submissions`、`/assignments/pending`、`/evaluation/:submissionId`、`/export` | 路由表写在 PR 描述或文档中 |
| P1 | 预留新增/删除操作 | 学生页预留新增表单和删除按钮，可先完成结构，后续再完整联调 | 不影响列表展示 |

## C 同学具体任务

| 优先级 | 任务 | 具体要求 | 验收方式 |
| --- | --- | --- | --- |
| P0 | 确认 CORS | 确认 `/api/**` 支持来自 `http://localhost:5173` 或前端实际端口的请求 | 前端页面能直接请求后端 |
| P0 | 保持学生接口稳定 | `GET /api/students` 返回学生数组；`POST /api/students` 接收 `studentNo`、`name`、`className`；`DELETE /api/students/{id}` 返回 204 | B 的学生页可以稳定对接 |
| P0 | 保持作业和评价接口稳定 | `GET /api/submissions`、`GET /api/evaluations`、`POST /api/submissions/{submissionId}/evaluate`、`POST /api/submissions/{submissionId}/teacher-review` 不随意改路径和字段 | Swagger 和真实返回一致 |
| P0 | 保持旧页面兼容 | 不要把所有成功响应统一改成 `{ code, message, data }`，除非旧页面 JS 和前端请求封装同步适配 | 旧 Thymeleaf 页面仍可正常展示 |
| P1 | 完善错误提示 | 参数错误继续返回 `{ "message": "..." }`；JSON 格式错误返回明确提示 | 前端能显示错误原因 |
| P1 | 核对 Swagger | 检查 `/swagger-ui/index.html` 中接口路径、请求体和返回说明 | Swagger 可作为 B 同学对接依据 |
