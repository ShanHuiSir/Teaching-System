# 安全与前端问题整改总结

本文档记录针对团队提出的安全与前端疑问所做的整改、当前状态和后续建议。

## 一、整改概览

本轮整改目标不是把演示项目改造成完整生产系统，而是先解决“可被直接绕过、演示时明显半成品、AI 接口可能被刷、关键操作无法追溯”等高风险问题。

已完成：

- 后端 API 增加统一登录认证过滤器。
- 登录改为真实后端接口，后端写入 HttpOnly 会话 Cookie。
- CORS 从全开放改为白名单配置。
- 写操作增加 `X-Requested-With` 请求头校验，降低普通 CSRF 风险。
- Java AI 评价入口和 Python 流式 AI 入口增加速率限制。
- 新增审计日志表和查询接口，记录登录、上传、评价、复核、导出、增删改等关键操作。
- 作业创建/编辑/删除改为真实接口。
- 班级创建/编辑/删除改为真实接口。
- 提交时间字段已由后端 `submittedAt` 输出，前端审批/趋势继续使用该字段。
- 仪表盘增加作业和班级筛选。
- 作业审批页“发布的作业”改为读取真实作业表数据。

## 二、安全问题处理

| 问题 | 整改情况 | 说明 |
|---|---|---|
| API 无认证 | 已处理 | 新增 `POST /api/auth/login` 和认证过滤器。除登录、健康检查、Swagger/OpenAPI 等公开路径外，`/api/**` 默认需要有效会话。 |
| 登录只是前端判断 | 已处理 | 前端不再本地硬编码判断账号密码，改为调用后端登录接口。 |
| CORS 全开 | 已处理 | `app.cors.allowed-origins` 默认只允许 `http://localhost:5173` 和 `http://127.0.0.1:5173`。生产环境需追加正式前端域名。 |
| API Key 明文风险 | 已处理/需持续遵守 | Python AI 服务从 `.env` 或环境变量读取 `DEEPSEEK_API_KEY`，仓库只保留 `.env.example`。如果真实 Key 曾经在聊天、截图或提交历史出现，需要在平台侧轮换。 |
| HTTPS 未启用 | 开发环境保留，生产建议 | 本地演示仍使用 HTTP。部署到服务器时建议由 Nginx、宝塔或云平台证书统一启用 HTTPS，并把 `app.auth.cookie-secure=true`。 |
| CSRF 防护不足 | 已做基础防护 | 会话 Cookie 设置 `SameSite=Lax`，前端统一带 `X-Requested-With: XMLHttpRequest`，后端写操作校验该头。生产级系统可继续补 CSRF Token。 |
| AI 接口无限流 | 已处理 | Java `/api/submissions/{id}/evaluate` 和 Python `/api/evaluate/real`、`/api/evaluate/stream` 均加每 IP 每分钟限制，默认 10 次。 |
| 无审计日志 | 已处理 | 新增 `audit_log` 表和 `GET /api/audit-logs` 查询接口，记录操作者、方法、路径、IP、状态码、时间等。 |

## 三、前端问题处理

| 问题 | 整改情况 | 说明 |
|---|---|---|
| 创建作业是半成品 | 已处理 | 作业管理页新增/编辑调用 `POST /api/assignments`、`PUT /api/assignments/{id}`。 |
| 删除作业是假删除 | 已处理 | 删除调用 `DELETE /api/assignments/{id}`；已有提交记录的作业后端拒绝删除。 |
| 创建班级是半成品 | 已处理 | 班级管理页新增/编辑调用 `POST /api/classes`、`PUT /api/classes/{id}`。 |
| 删除班级是假删除 | 已处理 | 删除调用 `DELETE /api/classes/{id}`；已有学生或作业关联的班级后端拒绝删除。 |
| 提交审批缺提交时间 | 已具备 | 后端 `WorkSubmission` 已有 `submittedAt`，前端审批列表、仪表盘趋势继续使用该字段。 |
| 仪表盘不能指定作业 | 已处理 | 仪表盘增加“全部作业/指定作业”和“全部班级/指定班级”筛选，并调用后端统计摘要筛选参数。 |
| 文件预览加载状态 | 已有基础能力 | 当前文件操作使用 `previewLoading`、`previewError`、骨架屏/占位组件。后续可继续统一视觉样式。 |

## 四、当前限制与答辩口径

- 当前认证是演示版轻量会话认证，不包含多教师、角色权限、密码加密存储和用户注册。
- 默认账号仍是 `teacher / 123456`，但可以用环境变量覆盖，避免写死到生产环境。
- 本地开发不启用 HTTPS，生产部署时通过反向代理启用。
- CSRF 已做基础防护，但如果作为正式系统上线，建议增加标准 CSRF Token。
- AI 限流为内存计数，适合单机演示；多实例生产部署建议改为 Redis 限流。
- 审计日志已记录关键请求，但尚未做后台审计页面和日志导出。

## 五、建议后续优先级

1. 部署前轮换 DeepSeek Key，并确认 `.env` 没有进入 Git 历史。
2. 生产环境启用 HTTPS，并设置 `app.auth.cookie-secure=true`。
3. 将演示账号改为环境变量配置，答辩现场不要展示真实密钥。
4. 如果继续扩展，优先加入角色权限、CSRF Token、Redis 限流和审计日志页面。
5. 继续统一文件预览的加载、失败、暂无预览三种状态样式。
