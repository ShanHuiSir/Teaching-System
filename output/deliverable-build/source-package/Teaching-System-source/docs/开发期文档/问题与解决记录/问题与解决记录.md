## 2026-05-28

### 问题：学生列表一次性查询存在 OOM 风险

### 问题

GitHub Issue #17 反馈：`StudentService.listStudents()` 直接调用 `studentRepository.findAll()`，当学生数量逐渐增多时，会一次性把全部学生加载到内存中，存在导致 OOM 的风险。

### 影响

- 学生管理页访问 `/api/students` 时可能一次性返回大量数据。
- 远程调试或真实教学班级数据变大后，后端内存压力和前端渲染压力都会增加。
- 后续如果导入大量学生，旧接口容易成为性能瓶颈。

### 原因分析

当前学生列表接口最初为小规模演示数据设计，默认只有 8 个学生，因此直接使用 `findAll()`。但该实现没有分页边界，随着数据增长不适合继续作为主查询方式。

### 解决办法

- 新增分页查询接口：

```text
GET /api/students/page?page=0&size=20
```

- `StudentService` 新增分页方法，使用 `PageRequest` 和 Spring Data JPA 分页查询。
- 对分页参数做保护：
  - `page` 小于 0 时按 0 处理。
  - `size` 最小为 1。
  - `size` 最大限制为 200。
- 保留旧接口 `GET /api/students` 作为兼容入口，但最多返回前 200 条学生记录，避免无限制 `findAll()`。
- 学生管理页改为调用分页接口，默认每页 20 条，并增加上一页、下一页和总数提示。

### 验证结果

- `mvn test` 执行通过。
- 学生管理页不再通过 `/api/students` 一次性加载全部学生，而是请求 `/api/students/page?page=0&size=20`。
- 旧接口仍可用于当前作业提交、评价等下拉框兼容场景，但已限制最多返回 200 条。

### 当前状态

已解决。2026-05-31 复盘时再次核对代码，确认分页接口和页面调用已落地：

- `GET /api/students/page?page=0&size=20&keyword=...`
- `StudentService.listStudents()` 兼容接口最多返回前 200 条
- 学生管理页改为调用分页接口

## 2026-05-31

### 问题：演示数据重置依赖硬编码 ID

### 问题

补自动化测试时发现，`DataInitializer.resetDemoData()` 清空数据后重新插入学生、作业和评价数据，但作业和评价初始化逻辑依赖 `1L`、`4L`、`6L` 等硬编码 ID。

### 影响

- H2 自增 ID 在删除数据后不一定回到 1。
- 多次调用重置接口或自动化测试反复重置数据时，评价记录可能关联到不存在的作业 ID。
- 演示数据看起来已重置，但状态页、统计或评价详情可能出现数据关联不一致。

### 原因分析

初始化逻辑假设学生和作业 ID 固定，但数据库自增主键不保证在 `deleteAll()` 后重置序列。

### 解决办法

- `seedStudents()` 改为返回实际保存后的学生列表。
- `seedSubmissions()` 使用学生实体的真实 `id` 和 `name` 建立作业关联。
- `seedEvaluations()` 使用实际保存后的作业 `id` 建立评价关联。
- 自动化测试中新增作业前也通过学生分页接口读取真实学生 ID，不再依赖固定 ID。

### 当前状态

已解决，`mvn -q test` 已通过。

## 2026-05-28

### 问题：开发环境缺少一键重置演示数据能力

### 问题

GitHub Issue #34 反馈：当前系统没有销毁 / 重置数据按钮，数据保存在 H2 内存数据库中，远程调试或多人联调时，如果学生、作业、评价数据被删除或改乱，难以快速恢复到初始化测试状态。

### 影响

- 学生管理页删除学生后，需要重启服务或手动操作 H2 才能恢复测试数据。
- 远程演示时数据状态不可控，容易影响主流程验收。
- 未审批、AI 已审批、已完成三个状态页的演示数据可能被前一次测试污染。

### 原因分析

项目当前使用 `DataInitializer` 在应用启动时灌入初始化数据，但只在启动阶段自动执行；运行过程中没有对外提供重置入口。H2 又是内存数据库，适合开发演示，但缺少页面按钮会让恢复数据不够直观。

### 解决办法

- 将 `DataInitializer` 的初始化逻辑拆出为可复用方法。
- 新增开发环境接口：

```text
POST /api/dev/reset-demo-data
```

- 接口执行时依次清空评价、作业、学生数据，再重新写入初始化学生、作业和评价结果。
- 使用 `@Profile("!prod")` 限制该接口只在非生产环境启用。
- 在学生管理页新增“重置数据”按钮，点击后弹出确认提示，确认后调用重置接口并重新加载学生列表。
- 重置成功后写入作业状态变更标记，通知状态页同步刷新。

### 验证结果

- 删除 1 个学生后，`/api/students` 返回数量从 8 变为 7。
- 调用 `POST /api/dev/reset-demo-data` 返回：

```json
{"message":"演示数据已重置"}
```

- 再次检查：
  - `/api/students` 返回 8 个学生。
  - `/api/submissions` 返回 6 条作业。
  - `/api/statistics/summary` 返回学生 8、作业 6、AI 已评价 3、教师已确认 1、教师平均分 92。
- `mvn test` 执行通过。

### 当前状态

已解决。

## 2026-06-02

### 问题：Py 服务启动依赖与 Python 版本兼容问题

### 问题

第 9 天启动 `ai-service` 时，先后遇到以下问题：

- `patool>=2.4.0` 在当前 pip 源中找不到可安装版本。
- `Evaluator`、`DocxConv`、`ArchiveProc`、`ScreenshotProc` 的 `pyproject.toml` 中 Python 版本要求偏高。
- 本机 Python 版本为 `3.9.6`，不支持 `int | None`、`str | Path` 等 Python 3.10 联合类型写法。
- `start.sh` 原本只安装 `DocxConv` 和 `Evaluator`，但实际服务运行还会导入 `ArchiveProc` 和 `ScreenshotProc`。

### 影响

- `./start.sh` 无法顺利启动 Py FastAPI 服务。
- Java-Py 真实预处理联调无法继续进行。

### 原因分析

- 依赖版本写得过高或与当前 pip 可用版本不一致。
- 子模块声明的 Python 版本要求高于当前本机环境。
- 部分代码使用了 Python 3.10+ 的类型标注语法，但本机使用 Python 3.9。
- 启动脚本没有安装所有运行时会导入的本地子包。

### 解决办法

- 将 `requirements.txt` 中 `patool>=2.4.0` 调整为 `py7zr>=0.20.0` 和 `rarfile>=4.0`。
- 将相关子模块 `requires-python` 放宽为 `>=3.9`。
- 将 Python 3.10 的 `A | B` 类型写法改为 `Union[...]` 或 `Optional[...]`。
- 修改 `start.sh` 和 `start.bat`，补充安装：

```text
DocxConv
Evaluator
ArchiveProc
ScreenshotProc
```

- 使用 `python3 -m py_compile` 对 `ai-service` 进行语法检查。

### 当前状态

已解决。Py FastAPI 服务已能启动，`http://localhost:8000/api/health` 可访问。

## 2026-06-03

### 问题：本地和线上 AI 服务路径前缀不同

### 问题

本地 Py FastAPI 服务直接暴露接口：

```text
http://localhost:8000/api/health
```

线上 Swagger 中 AI 服务通过网关前缀访问：

```text
https://redtree.miprota.cc/ai/api/health
```

如果不说明清楚，队友可能把线上 `/ai` 前缀误认为 Py 服务内部路径。

### 影响

- C 同学本地调试时如果访问 `/ai/api/health`，会找不到接口。
- B 同学或老师在线上 Swagger 测试 AI 服务时，如果访问 `/api/health`，会绕过线上代理前缀，导致路径不一致。
- Java-Py 联调记录容易出现“本地和线上接口不一致”的误解。

### 原因分析

Py 服务内部接口本体是 `/api/**`；线上部署时由 nginx 或网关将 `/ai/**` 转发到 Py 服务，因此线上公开路径多了 `/ai` 前缀。

### 解决办法

- 本地调试统一使用：

```text
http://localhost:8000/api/health
http://localhost:8000/api/preprocess
http://localhost:8000/api/evaluate/real
```

- 线上 Swagger / 线上访问统一使用：

```text
https://redtree.miprota.cc/ai/api/health
https://redtree.miprota.cc/ai/api/preprocess
https://redtree.miprota.cc/ai/api/evaluate/real
```

- 文档中明确 `/ai` 是线上代理前缀，不是 Py FastAPI 内部路由。

## 2026-06-04

### 问题：真实 AI 已验证，但最终演示仍需默认降级兜底

### 问题

第 11 天已确认 `/api/evaluate/real` 能返回 `aiScore/aiIssues/aiComment`。但真实 AI 仍依赖外部 Key、网络和模型服务，不能把演示主流程强绑定到外部服务可用性上。

### 影响

- 外部模型接口波动可能导致演示时评分超时或失败。
- 如果强制开启 `app.ai.real.enabled=true`，演示稳定性会低于 FakeAI 模式。

### 原因分析

Java 侧已经实现 `DelegatingAIService`：

- 默认使用 `FakeAIService`。
- 开启 `app.ai.real.enabled=true` 后调用 `RealAIService`。
- 真实 AI 异常时降级回 FakeAI。

这个设计本身就是为了兼顾真实能力和演示稳定性。

### 解决办法

- 最终演示默认保持：

```properties
app.ai.real.enabled=false
```

- 如需展示真实 AI，临时开启：

```properties
app.ai.real.enabled=true
app.ai.real.endpoint-url=http://localhost:8000/api/evaluate/real
```

或线上代理路径：

```text
https://redtree.miprota.cc/ai/api/evaluate/real
```

- 演示口径明确为：真实 AI 已接通，可配置开启；默认保留 FakeAI 兜底，避免外部服务影响验收。

### 当前状态

已验证并记录。不阻塞最终版交付。
