# 08-文件命名规范

## 总体原则

- 文件名能表达用途，不缩写、不拼音。
- 同类文件保持一致的命名风格。
- Java 使用大驼峰（PascalCase），HTML/CSS/SQL 使用小写英文。
- Markdown 文档使用中文名 + 序号前缀或日期前缀。

---

## Java 源文件

### 包结构

```
com.teachingeval
├── config/        # 配置类
├── controller/    # REST 控制器  (@RestController)  + 全局异常处理
├── dto/           # 数据传输对象（请求体 / 响应体）
├── entity/        # JPA 实体（@Entity）
├── repository/    # 数据访问接口（Spring Data JPA）
├── service/       # 服务接口
└── service/impl/  # 服务实现
```

### 后缀规范

| 类型             | 后缀                     | 示例                                     |
|----------------|------------------------|----------------------------------------|
| Spring Boot 入口 | `{Project}Application` | `TeachingSystemApplication`            |
| 配置类            | `*Config`              | `OpenApiConfig`                        |
| REST 控制器       | `*Controller`          | `StudentController`                    |
| 全局异常处理         | `*ExceptionHandler`    | `ApiExceptionHandler`                  |
| 服务接口           | `*Service`             | `EvaluationService`                    |
| 服务实现           | 接口名（放 `impl/` 包）       | `FakeAIService`                        |
| 数据访问接口         | `*Repository`          | `StudentRepository`                    |
| JPA 实体         | 无后缀                    | `Student`、`WorkSubmission`             |
| 接口入参           | `*Request`             | `AIEvalRequest`、`TeacherReviewRequest` |
| 接口出参           | `*Response`            | `StatisticsSummaryResponse`            |

### DTO 命名规则

`dto/` 包下按数据流向区分后缀，不再统一使用 `DTO`：

| 流向        | 后缀          | 示例                                     |
|-----------|-------------|----------------------------------------|
| 客户端 → 服务端 | `*Request`  | `AIEvalRequest`、`TeacherReviewRequest` |
| 服务端 → 客户端 | `*Response` | `StatisticsSummaryResponse`            |

### 文件与类名一致

Java 文件名必须与 public 类名完全一致，遵循大驼峰：

```
StudentController.java           → public class StudentController
AIEvalRequest.java                → public class AIEvalRequest
StatisticsSummaryResponse.java    → public record StatisticsSummaryResponse
```

## 前端文件

### Vue 单文件组件（.vue）

PascalCase（大驼峰），一个文件一个组件：

```
LoginPage.vue
MainLayout.vue
MagicBar.vue
ActionButton.vue
EmptyState.vue
SearchInput.vue
```

- **页面组件**：`*Page.vue` 后缀（如 `LoginPage.vue`、`ReviewPage.vue`）
- **布局组件**：描述性名称（如 `MainLayout.vue`）
- **UI 组件**：PascalCase 无后缀（如 `MagicBar.vue`、`EmptyState.vue`）

### TypeScript（.ts）

小写英文，kebab-case 或 camelCase：

```
main.ts                    # 入口文件
env.d.ts                   # 类型声明文件
types.ts                   # 共享类型定义
```

工具模块：
```
request.ts                 # HTTP 客户端
cookie.ts                  # Cookie 工具
cookiePrefs.ts             # Cookie 偏好
fileIcons.ts               # 文件图标映射
recoveryPoll.ts            # 恢复轮询
```

路由：
```
router/index.ts            # 路由定义
```

### Composables（.ts）

`use` 前缀 + camelCase：

```
useMagicBar.ts             # 状态栏状态机
useDraft.ts                # 草稿存取
useSnackbar.ts             # 全局通知
useTheme.ts                # 主题管理
```

### SCSS 模块

kebab-case，下划线前缀表示 partial（不独立编译）：

```
styles/
  _mixins.scss             # 共享 mixin + 变量
```

### 配置文件

| 文件 | 说明 |
|------|------|
| `vite.config.ts` | Vite 构建配置 |
| `tsconfig.json` | TypeScript 主配置 |
| `tsconfig.node.json` | TypeScript Vite 配置 |
| `eslint.config.js` | ESLint 规则（flat config） |
| `.prettierrc` | Prettier 格式化规则 |
| `package.json` | 依赖与脚本 |

## Markdown 文档

### 设计期文档

```
序号-中文描述.md
```

示例：

```
00-设计期文档目录.md
01-项目概述与需求分析.md
02-业务流程设计.md
```

规则：
- 两位数字序号，不足两位补 0。
- 数字与中文描述之间用短横线 `-` 连接。
- 标题中的空格用 `-` 代替。

### 日进度汇报表

```
YYYY-MM-DD-描述.md
```

示例：

```
2026-05-26-日进度汇报表.md
```

### 工作清单

```
第N天-任务描述.md
```

示例：

```
第1天-前端页面清单.md
第1天-队长对接清单.md
```

### 根目录文档

大写英文，遵循惯例：

```
README.md
CLAUDE.md
```
