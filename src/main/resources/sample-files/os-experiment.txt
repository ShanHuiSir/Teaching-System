操作系统实验报告：进程调度算法对比分析

一、实验目的
通过实现和对比三种经典进程调度算法（FCFS、SJF、RR），深入理解不同调度策略
对系统性能的影响，掌握平均等待时间、平均周转时间等关键指标的计算方法。

二、实验环境
操作系统：Ubuntu 22.04 LTS
编程语言：C++
编译器：g++ 11.4.0

三、算法实现

1. 先来先服务（FCFS）
按照进程到达的先后顺序分配 CPU。实现简单，但对短进程不利，
容易产生"护航效应"——长进程阻塞后面的短进程。

核心代码：
void fcfs_schedule(std::vector<Process>& processes) {
    std::sort(processes.begin(), processes.end(),
              [](const Process& a, const Process& b) { return a.arrival < b.arrival; });
    int current_time = 0;
    for (auto& p : processes) {
        if (current_time < p.arrival) current_time = p.arrival;
        p.waiting_time = current_time - p.arrival;
        current_time += p.burst;
        p.turnaround_time = p.waiting_time + p.burst;
    }
}

2. 最短作业优先（SJF）
优先调度预计执行时间最短的进程。可以最小化平均等待时间，
但需要预知进程的执行时间，实际系统中难以实现。

3. 时间片轮转（RR）
每个进程分配固定时间片（如 4ms），用完时间片后回到就绪队列尾部。
响应时间好，适合交互式系统，但上下文切换开销较大。

四、实验结果
| 算法 | 平均等待时间 | 平均周转时间 | CPU 利用率 |
|------|------------|------------|-----------|
| FCFS | 15.2ms     | 28.6ms     | 92.3%     |
| SJF  | 8.4ms      | 21.8ms     | 94.1%     |
| RR   | 11.3ms     | 25.1ms     | 89.7%     |

五、结论
SJF 在平均等待时间和周转时间上表现最优，但依赖准确的执行时间预测。
RR 在响应性和公平性方面更优，适合交互式系统。
FCFS 实现最简单，但在混合负载场景下性能较差。
