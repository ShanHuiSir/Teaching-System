# 教学评价系统部署方案

## 一、部署环境要求

### 1. 验收要求（必须满足）
- **操作系统**：麒麟高级服务器版
- **CPU 架构**：LoongArch（`uname -m` 应输出 `loongarch64`）

### 2. 推荐系统环境
- **Java**: JDK 17（OpenJDK 17）
- **Maven**: 3.6+
- **Node.js**: 18+
- **npm**: 8+
- **Python**: 3.10+（AI 服务可选）

### 3. 服务端口
- **前端**: 5173
- **后端**: 8080
- **AI 服务**: 8000（可选，演示环境可降级）

---

## 二、部署方式选择

根据使用场景选择合适的部署方案：

| 场景 | 推荐方式 | 说明 |
|------|----------|------|
| **验收演示** | 原生启动脚本 | 在 LoongArch 麒麟虚拟机内运行，保证架构合规 |
| **日常开发** | 手动启动三服务 | 灵活调试，查看日志 |
| **生产环境** | Docker Compose | 隔离环境，一键部署 |
| **快速测试** | 一键启动脚本 | 本地快速验证功能 |

## 三、方式一：原生启动（推荐用于验收）

### 1. 环境准备

```bash
# 安装基础工具
sudo dnf install -y git java-17-openjdk java-17-openjdk-devel maven nodejs npm curl net-tools psmisc
# 或使用 apt
sudo apt update
sudo apt install -y git openjdk-17-jdk maven nodejs npm curl net-tools psmisc

# 验证环境（录屏建议）
uname -m                    # 应为 loongarch64
cat /etc/os-release         # 应为麒麟系统
java -version
mvn -v
node -v
npm -v
```

### 2. 获取项目

```bash
cd ~
git clone <你的项目仓库地址> Teaching-System
cd Teaching-System
```

### 3. 启动演示环境

```bash
# 赋予执行权限
chmod +x start-kylin-loongarch-demo.sh

# 启动（后端使用 demo 配置，关闭真实 AI 依赖）
./start-kylin-loongarch-demo.sh
```

### 4. 访问系统

| 服务 | 地址 |
|------|------|
| 前端页面 | `http://localhost:5173` |
| 后端健康检查 | `http://localhost:8080/api/health` |
| Swagger UI | `http://localhost:8080/swagger-ui/index.html` |

**登录账号**：`teacher / 123456`

### 5. 宿主机访问虚拟机

```bash
# 查看虚拟机 IP
ip addr

# 宿主机访问（替换为实际 IP）
http://虚拟机IP:5173

# 如访问不通，检查防火墙
sudo firewall-cmd --add-port=5173/tcp --permanent
sudo firewall-cmd --add-port=8080/tcp --permanent
sudo firewall-cmd --reload
```

### 6. 停止服务

```bash
fuser -k 8080/tcp 5173/tcp
```

## 四、方式二：Docker Compose 部署

### 1. 环境要求

- Docker 20+
- Docker Compose

**注意**：LoongArch 上官方 Docker 镜像可能不全，建议在普通 Linux 服务器使用此方式。

### 2. 配置环境变量

```bash
# 创建 .env 文件
cat > .env << EOF
DEEPSEEK_API_KEY=你的API密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_THINKING=false
DEEPSEEK_MAX_TOKENS=4096
OCR_ENABLED=false
EOF

# 设置权限
chmod 600 .env
```

### 3. 构建并启动

```bash
# 编译后端 JAR
mvn -DskipTests package

# 启动服务（构建 + 启动）
docker compose up --build -d

# 查看状态
docker compose ps

# 查看日志
docker compose logs -f backend
docker compose logs -f ai-service
docker compose logs -f frontend
```

### 4. 访问系统

与原生启动相同：
- 前端：`http://localhost:5173`
- 后端：`http://localhost:8080/api/health`
- Swagger：`http://localhost:8080/swagger-ui/index.html`

### 5. 停止服务

```bash
docker compose down
```

## 五、方式三：手动启动三服务

### 1. 启动 AI 服务（可选，演示可跳过）

```bash
cd ai-service

# 创建虚拟环境
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate.bat

# 安装依赖

# 启动服务
python -m docxconv serve --host 0.0.0.0 --port 8000
```

```bash

# 编译
mvn compile

# 运行（使用 demo 配置）
mvn spring-boot:run -Dspring-boot.run.profiles=demo

# 或使用真实 AI 配置
mvn spring-boot:run
```

### 3. 启动前端

```bash
cd frontend

# 安装依赖（首次）
npm install

# 运行
npm run dev
```

### 4. 访问系统

- 前端：`http://localhost:5173`
- 后端：`http://localhost:8080/api/health`

## 七、配置文件说明

### 1. Spring Boot 配置文件

| 配置文件 | 用途 | 启用方式 |
|----------|------|----------|
| `application.properties` | 默认配置 | 默认启动 |
| `application-demo.properties` | 演示配置（关闭真实 AI） | `mvn spring-boot:run -Dspring-boot.run.profiles=demo` |
| `application-docker.properties` | Docker 环境配置 | `docker compose up` 时自动设置 `SPRING_PROFILES_ACTIVE=docker` |
| `application-fake.properties` | 假 AI 配置 | 手动指定 |
| `application-dev.properties` | 本地开发配置 | 手动指定 |
| `application-prod.properties` | 生产环境配置 | 手动指定 |

### 2. 关键配置项

#### 认证配置

```properties
app.auth.username=teacher          # 默认用户名
app.auth.password=123456          # 默认密码
app.auth.accounts=temp:123456     # 额外账号（逗号分隔）
```

#### AI 服务配置

```properties
app.ai.real.enabled=true                           # 是否启用真实 AI
app.ai.real.endpoint-url=http://localhost:8000/api/evaluate/real
app.ai.rate-limit-per-minute=10                    # AI 调用速率限制
```

#### 文件上传

```properties
app.upload.root=uploads            # 上传文件存储目录
spring.servlet.multipart.max-file-size=50MB
spring.servlet.multipart.max-request-size=60MB
```

#### CORS 跨域

```properties
app.cors.allowed-origins=http://localhost:5173,http://127.0.0.1:5173
```

## 九、常见问题

### 1. 端口被占用

```bash
# 查找占用进程
lsof -ti :8080
ss -tlnp | grep :8080

# 杀死进程
fuser -k 8080/tcp 5173/tcp 8000/tcp
# 或
lsof -ti :8080 | xargs kill -9
```

### 2. Maven 编译失败

```bash
# 清理并重新编译
mvn clean compile

# 跳过测试
mvn clean compile -DskipTests

# 查看详细错误
mvn compile -X
```

### 3. npm 安装慢

```bash
# 使用国内镜像
npm config set registry https://registry.npmmirror.com

# 重新安装
rm -rf node_modules package-lock.json
npm install
```

### 4. AI 服务未启动，但需要演示

后端 `application-demo.properties` 已关闭真实 AI 调用，使用 `FakeAIService` 降级返回演示评分（82.50 分），不影响主流程演示。

### 5. Swagger UI 无法访问

检查后端是否正常启动，访问 `http://localhost:8080/api/health` 确认服务健康。

### 6. 跨域问题

确认 `app.cors.allowed-origins` 包含前端访问地址。Docker 环境中通过环境变量 `APP_CORS_ALLOWED_ORIGINS` 设置。

## 十一、CI/CD 部署（GitHub Actions）

项目已配置 GitHub Actions 工作流 `.github/workflows/deploy.yml`，支持自动部署到远程服务器。

### 工作流程

1. **触发条件**：`main` 分支推送，且修改了关键文件
2. **构建阶段**：
   - Maven 编译后端
   - 准备 Docker 部署目录
3. **上传阶段**：通过 SSH 将构建产物上传到服务器
4. **部署阶段**：在服务器上执行 `docker compose build` 和 `docker compose up -d`

### 配置要求

在 GitHub 仓库的 Secrets 中配置：

| Secret | 说明 |
|--------|------|
| `SERVER_HOST` | 服务器地址 |
| `SERVER_USER` | SSH 用户名 |
| `SERVER_SSH_KEY` | SSH 私钥 |
| `SERVER_PORT` | SSH 端口（默认 21987） |
| `DEEPSEEK_API_KEY` | DeepSeek API 密钥 |

## 十三、架构决策说明

### 为什么验收演示推荐原生启动而非 Docker？

1. **架构合规性**：LoongArch 上部分官方 Docker 镜像（`node:22-alpine`、`python:3.11-slim`）可能不存在或不稳定
2. **依赖兼容性**：Python AI 服务的 OCR 依赖（EasyOCR/Torch）在 LoongArch 上可能无法正常安装
3. **演示稳定性**：原生启动不依赖外部镜像源，保证核心教学评价闭环可稳定展示
4. **录屏清晰度**：直接在虚拟机内运行，环境证明更直观（`uname -m`、`cat /etc/os-release`）

### AI 服务降级策略

- **正常模式**：后端调用 Python AI 服务（`http://localhost:8000/api/evaluate/real`）
- **降级模式**：AI 服务不可用时，自动使用 `FakeAIService` 返回演示评分（82.50 分）
- **双重保险**：Python 服务内部也有降级逻辑，API 调用失败时返回默认评分

## 十四、后续扩展建议

### 1. 多环境配置

当前已有 `demo`、`docker`、`dev`、`prod` 配置文件，可根据实际部署环境扩展。

### 2. Nginx 反向代理

生产环境建议配置 Nginx 反向代理：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://localhost:5173;
    }

    location /api/ {
        proxy_pass http://localhost:8080;
    }

    location /ai/ {
        proxy_pass http://localhost:8000;
    }
}
```

### 3. 数据库迁移

当前使用 H2 内存数据库，生产环境建议迁移到 MySQL：

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/teaching_eval
spring.datasource.username=root
spring.datasource.password=your_password
spring.jpa.hibernate.ddl-auto=update
```

### 4. HTTPS 配置

使用 Let's Encrypt 免费证书：

```bash
sudo certbot --nginx -d your-domain.com
```
