# 项目文档说明

本目录用于保存教学评价系统的设计文档、开发过程记录和汇报材料。文档统一使用 Markdown 编写，并随代码一起提交到 GitHub，方便查看历史版本和修改记录。

## 当前基线

当前项目主线以 `main` 分支为准。前端已经迁移为 Vue 3 SPA，业务入口为 `/dashboard`、`/classes`、`/assignments`、`/review`；旧 Thymeleaf 模板、独立学生页、独立导出页和旧 Sidebar 已从代码主线移除。

`工作清单/` 和早期 `开发期文档/日进度汇报表/` 记录开发过程，可能包含当时的 `/students`、`/works`、`/evaluation`、`/export`、Thymeleaf 等旧口径。它们保留为历史追溯材料，不作为最新任务入口。

## 文档目录

| 目录 | 用途 | 维护方式 |
| --- | --- | --- |
| `设计期文档/` | 说明系统要做什么、业务怎么走、页面有哪些、命名规范是什么 | 当前设计变化时更新，优先保持与 `main` 一致 |
| `开发期文档/日进度汇报表/` | 每天记录个人或小组进度 | 每天新增一份 |
| `开发期文档/数据库变更/` | 记录表结构和字段变化 | 数据库有变化时新增或追加 |
| `开发期文档/测试记录/` | 记录关键流程测试结果 | 每次阶段验收时新增 |
| `开发期文档/问题与解决记录/` | 记录开发、部署、联调中的问题 | 遇到影响项目的问题时追加 |
| `工作清单/` | 保存早期任务拆分和分工记录 | 保留历史，不作为最新任务入口 |
| `interface/` | 保存早期接口说明；详细接口以后以 Swagger 为准 | 需要时补充说明 |
| `设计规范/` | 保存早期数据库字段设计等规范 | 后续可逐步迁移到设计期文档 |

## GitHub 是否适合放文档

适合。原因：

- Markdown 文档可以直接在 GitHub 页面阅读。
- 每次修改都有 Git 历史，方便追踪是谁、什么时候改了什么。
- 文档和代码放在同一个仓库，避免代码更新了但文档找不到。
- 老师或队友可以通过链接直接查看文档。

## 写报告放在哪里

每日汇报放在：

```text
docs/开发期文档/日进度汇报表/
```

命名格式：

```text
YYYY-MM-DD-日进度汇报表.md
```

例如：

```text
docs/开发期文档/日进度汇报表/2026-05-26-日进度汇报表.md
```

设计期文档放在：

```text
docs/设计期文档/
```

数据库变化放在：

```text
docs/开发期文档/数据库变更/
```

测试记录放在：

```text
docs/开发期文档/测试记录/
```

## 接口文档维护原则

详细接口设计以 Swagger / OpenAPI 为主，包括接口路径、请求参数、返回值和说明。

Markdown 文档只记录总体方针、重要约定和 Swagger 不适合表达的内容，例如：

- 为什么设计这些接口。
- 哪些接口已经实现，哪些还在计划中。
- 数据库变更原因。
- 每日进度和问题处理过程。
