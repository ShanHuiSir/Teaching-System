# 阶段计划与范围边界

## 阶段计划

| 阶段 | 主要内容 | 目标 |
| --- | --- | --- |
| 第一阶段 | 设计期文档和 HTML 原型 | 先把业务流程、页面和数据关系讲清楚 |
| 第二阶段 | 学生管理和作品提交基础功能 | 完成学生信息维护和作品登记 |
| 第三阶段 | FakeAIService 模拟 AI 评价 | 先用假 AI 跑通评价流程 |
| 第四阶段 | 教师复核和成绩统计 | 保存教师最终评分并展示统计结果 |
| 第五阶段 | Excel 导出 | 导出最终成绩表 |
| 第六阶段 | 接入真实大模型 | 将 FakeAIService 替换为真实 AI 接口 |

## 当前阶段范围

当前阶段重点是完成新版教师端工作台的收口验收：

- Vue 3 SPA 作为唯一前端主线，路由以 `/login`、`/dashboard`、`/classes`、`/assignments`、`/review` 为准。
- 学生管理归入班级页，作业数据导出归入作业管理页。
- 作业审批支持 AI 评价、SSE 流式评分、分维度评分展示和教师复核。
- Java 后端保持学生、提交、评价、统计、导出、健康检查等 REST API 稳定。
- Python AI 服务承担预处理、真实评分和流式评分能力；Java 在 Python 不可用时保留 FakeAI 降级。
- 开发演示数据初始化、重置、构建、测试和文档基线保持一致。

## 当前阶段暂不做

- 不做复杂权限系统。
- 不做学生端和管理员端。
- 不恢复旧 Thymeleaf 页面、旧 Sidebar、独立学生页、独立导出页。
- 不在本阶段强行完成完整多租户/多教师权限。
- 多文件提交、正式班级表、正式作业表、账号表和云端草稿属于下一轮数据模型重构，不再按旧页面补功能。

## 后续实现原则

- 先以当前 Vue 工作台确认业务流程。
- 再补齐后端数据模型和接口，不让前端长期依赖派生数据。
- 详细接口以 Swagger / OpenAPI 为准。
- 每次功能变化同步更新相关文档。
