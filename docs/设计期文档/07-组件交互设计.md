# 07-组件交互设计

## 概述

前端基于 Vue 3 Composition API（`<script setup lang="ts">`），采用 **provide/inject** 模式实现跨层级通信，**composables** 封装可复用状态逻辑，**12 个共享组件** 消除页面间重复。

## 跨组件通信：provide / inject

MainLayout 通过 Vue 的 `provide()` 向下传递共享状态，各页面通过 `inject()` 消费。使用 TypeScript `InjectionKey` 确保类型安全（定义在 `src/types.ts`）。

| InjectionKey | 类型 | 提供方 | 消费者 |
|-------------|------|--------|--------|
| `MAGIC_BAR_KEY` | `MagicBar` (reactive) | MainLayout → useMagicBar | 所有页面：设置 primary/sub/suffix/status |
| `TRIGGER_RIPPLE_KEY` | `(cx?, cy?) => void` | MainLayout → useMagicBar | 各页面：提交成功时触发涟漪特效 |
| `SHOW_GREETING_KEY` | `(pagePrimary: string) => void` | MainLayout → useMagicBar | 各页面：onActivated 时触发问候语 |
| `REFRESH_TICK_KEY` | `Ref<number>` | MainLayout | 各页面：手动刷新触发 |
| `RIGHT_BUTTONS_KEY` | `Ref<RightButton[]>` | MainLayout（供页面写入） | 各页面：onActivated 时设置右侧工具栏按钮，onDeactivated 时清空 |

### 页面集成模式

```typescript
// 每个页面在 onActivated 时设置 MagicBar 标题和右侧工具栏
onActivated(() => {
  magicBar.primary = '作业审批'
  magicBar.sub = '全部作业'
  rightButtons.value = [
    { key: 'sort-time', icon: '...', label: '按时间排序', active: sortTime.value, action: () => { ... } },
  ]
})
onDeactivated(() => { rightButtons.value = [] })
```

## Composables（可复用状态逻辑）

| Composable | 文件 | 用途 |
|------------|------|------|
| `useMagicBar` | `composables/useMagicBar.ts` | 状态栏状态机（问候语、休息提醒、连接健康、涟漪） |
| `useDraft` | `composables/useDraft.ts` | 表单草稿 Cookie 存取（自动保存、关闭提示、恢复检测） |
| `useSnackbar` | `composables/useSnackbar.ts` | 全局通知栏（单例 ref 驱动，跨组件共享） |
| `useTheme` | `composables/useTheme.ts` | 主题管理（亮色/暗色/自动，localStorage 持久化） |

### useMagicBar 内部状态机

```
MagicBar 状态优先级：
  status (最高) → primary + greeting/sub + suffix (常规)

子状态系统：
  ┌─ Greeting: 300ms 延迟 → 5s 自动消失
  ├─ Rest Reminder: 60min 无操作 → 6s 状态提示
  ├─ Connection Health: recoveryPoll 驱动 → 断连/重连提示
  └─ Ripple: 页面提交成功 → CSS animation
```

### useDraft 草稿流程

```text
编辑开始 (editing = true)
  → watchEffect 自动保存到 Cookie（7 天）
  → watch editing: false 检测未提交关闭 → Snackbar 提示

页面加载时
  → loadDraft() 尝试恢复草稿
  → 若已提交 (status >= 2) → 自动清除草稿

提交成功
  → clearDraft() 删除 Cookie
```

## 三面板滑动布局

ReviewPage、ClassesPage、AssignmentsPage 共用此布局模式：

```
Panel 1（始终可见）   Panel 2（条件滑动）     Panel 3（条件滑动）
占 50% 宽度            transform: translateX   transform: translateX
                       activeId 有值时 → 0     编辑时 → -100%
                       无值时 → 100%           非编辑时 → 100%
```

- 所有面板使用 CSS `transition: transform .4s cubic-bezier(.4, 0, .2, 1)`
- Panel 2 显示详情：由 `activeId` 控制
- Panel 3 显示表单：由 `editing` 控制

## 数据获取与错误处理

### HTTP 层（request.ts）

- Axios 实例 baseURL `/api`，Vite 代理到 `localhost:8080`
- 响应拦截器：`code === 200` → 解包返回 `body.data`；其他 → reject
- 网络错误 / 500 → 通知离线 + 限流（10s 内不重复弹）

### 恢复轮询（recoveryPoll.ts）

```text
请求失败 → startRecoveryPoll(() => fetchAll())
         → 每 3s 轮询 GET /health
         → 成功 → 触发回调（重新拉数据） → 清除轮询
```

### 错误边界（ErrorBoundary）

- `onErrorCaptured` 捕获子树渲染错误
- 显示"山重水复疑无路，柳暗花明又一村" + 重新加载按钮


## 路由与认证流

```text
App 启动
  → router.beforeEach()
  → 检查 auth_token Cookie
  → 需要认证的页面无 token → /forbidden
  → /login 已登录 → /
  → /forbidden 已登录 → /
```

=== 2026.6.8 ===

1. **SSE 心跳连接监控**：`recoveryPoll.ts` 用 `EventSource('/api/heartbeat')` 长连接替代旧 3s HTTP 轮询。浏览器按服务器 `retry:5000` 指令自动重连，前端只监控心跳是否到达（15s 超时→断连）。`useMagicBar` 通过 `useConnectionHealth` 消费状态变更，驱动 MagicBar 断连/重连 UI 和 Snackbar 通知。
2. **页面级数据重试**：`request.ts` 新增 `retryFetch(fn, onError)`，取代旧 `startRecoveryPoll`。页面 `onMounted` 中包装 fetch 函数，失败后自动 1s→2s→4s→...→15s 退避重试。不再依赖 SSE 连接状态来触发数据重拉。
3. **骨架屏加载**：`ListSkeleton.vue` 提供列表级 shimmer 占位卡片，`ContentSkeleton.vue` 提供全页三面板骨架。首次加载数据到达前显示骨架，保持外壳可见。
4. **草稿 composable**：`useDraft.ts` 封装表单草稿的 Cookie 存取（`loadDraft`/`saveDraft`/`clearDraft`），含 `watchEffect` 自动保存和关闭未提交提示。`AssignmentsPage` 和 `ClassesPage` 共用。
5. **AI 流式评分交互**：`onAiEval` 流程改为 `GET /api/submissions/{id}/file`→`FormData`→`POST /api/evaluate/stream`（Python SSE），前端 `ReadableStream` 逐块消费。`reasoning`/`content`/`dimension_*`/`result` 事件分别驱动 MagicBar 状态、骨架→实时维度条、流式文本累积、evalMap 写入+数据库持久化。
