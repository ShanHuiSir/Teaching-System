# 05-接口设计总体方针

## 核心原则

1. **页面和 API 分离**：页面路由（`@Controller`）与 REST API（`@RestController`）分属两类 Controller，路径体系不同。
2. **资源导向**：URL 围绕资源命名（`/students`、`/submissions`），操作由 HTTP 方法区分。
3. **Swagger 优先**：Swagger UI 是接口的权威文档，所有变更必须同步体现在注解中。

## URL 路径规范

### REST API 前缀

所有 REST 接口统一使用 `/api` 前缀，通过类级 `@RequestMapping("/api")` 实现：

```java
@RestController
@RequestMapping("/api")
public class XxxController { ... }
```

### 资源路径命名

| 规则 | 示例 |
|---|---|
| 资源名用名词复数 | `/api/students`、`/api/submissions` |
| 子资源嵌套在父资源路径下 | `/api/submissions/{submissionId}/evaluate` |
| 用短横线分隔多词 | `/api/submissions/{submissionId}/teacher-review` |
| 不用驼峰或下划线 | 禁止 `/teacherReview`、`/teacher_review` |

### HTTP 方法与路径组合

| HTTP 方法 | 路径模式 | 语义 |
|---|---|---|
| `GET` | `/api/{资源}` | 列表查询 |
| `GET` | `/api/{资源}/{id}` | 单体查询 |
| `POST` | `/api/{资源}` | 新建 |
| `POST` | `/api/{资源}/{id}/{动作}` | 资源上的操作 |
| `DELETE` | `/api/{资源}/{id}` | 删除 |

## 参数传递规范

### 路径参数（@PathVariable）

用于资源标识符（ID），类型统一使用 `Long`：

```java
@GetMapping("/submissions/{submissionId}/evaluation")
public AIEvaluationResult getEvaluation(@PathVariable Long submissionId) { ... }
```

### 请求体（@RequestBody）

用于 POST 的数据载体，使用专用 DTO 封装：

```java
@PostMapping("/submissions/{submissionId}/teacher-review")
public AIEvaluationResult saveTeacherReview(@PathVariable Long submissionId,
                                            @RequestBody TeacherReviewRequest request) { ... }
```

### 查询参数（@RequestParam）

**REST 层禁止使用 `@RequestParam`**。过滤、分页等场景优先使用路径和请求体。

仅页面 Controller（`@Controller`）的表单提交允许使用 `@RequestParam`。

## HTTP 状态码规范

| 场景 | 状态码 | 注解 |
|---|---|---|
| 查询成功 | `200 OK` | 默认，无需额外注解 |
| 创建成功 | `201 Created` | `@ResponseStatus(HttpStatus.CREATED)` |
| 删除成功（无返回体） | `204 No Content` | `@ResponseStatus(HttpStatus.NO_CONTENT)` |
| 参数校验失败 | `400 Bad Request` | 全局异常处理器统一处理 |

示例：

```java
@PostMapping("/students")
@ResponseStatus(HttpStatus.CREATED)
public Student createStudent(@Valid @RequestBody StudentRequest request) { ... }

@DeleteMapping("/students/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void deleteStudent(@PathVariable Long id) { ... }
```

## 异常处理

业务层抛出 `IllegalArgumentException`，全局 `@RestControllerAdvice` 统一转换为 400 响应：

```java
@ExceptionHandler(IllegalArgumentException.class)
@ResponseStatus(HttpStatus.BAD_REQUEST)
public ErrorResponse handleIllegalArgumentException(IllegalArgumentException exception) {
    return new ErrorResponse(exception.getMessage());
}
```

无需在每个 Controller 中写 try-catch。

## 注入方式

**强制使用构造器注入**，禁止 `@Autowired` 字段注入：

```java
@RestController
@RequestMapping("/api")
public class XxxController {

    private final XxxService xxxService;

    public XxxController(XxxService xxxService) {
        this.xxxService = xxxService;
    }
}
```

## Swagger 文档规范

### Controller 类

```java
@Tag(name = "学生管理")
@RestController
@RequestMapping("/api")
public class StudentController { ... }
```

### 方法

```java
@Operation(summary = "创建学生", description = "根据学号、姓名、班级创建一名新学生，通过 StudentRequestDTO 校验必填字段。")
@PostMapping("/students")
@ResponseStatus(HttpStatus.CREATED)
public Student createStudent(@Valid @RequestBody StudentRequest request) { ... }
```

### 注意

- `summary` 简短概括，`description` 补充细节。
- `@Tag` 的 `name` 使用中文，简洁明了。
- 页面 Controller（`@Controller`）不需要 Swagger 注解。

## 返回值类型

| 场景 | 返回类型 |
|---|---|
| 查询单体 / 操作结果 | Entity 或 DTO |
| 查询列表 | `List<Entity>` 或 `List<DTO>` |
| 简单状态 | `Map<String, String>` |
| 无返回体 | `void`（配合 204） |

## 设计检查清单

新增或修改接口时，逐项确认：

- [ ] 路径是否以 `/api` 开头？
- [ ] 路径是否使用名词复数、短横线分隔？
- [ ] 资源 ID 是否通过 `@PathVariable` 传递？
- [ ] POST 数据是否封装为专用 DTO？
- [ ] 是否使用了 `@RequestParam`？（REST 层不允许）
- [ ] 是否使用构造器注入而非 `@Autowired`？
- [ ] 是否标注了 `@Tag` 和 `@Operation`？
- [ ] 创建/删除是否标注了正确的 HTTP 状态码？
- [ ] 异常是否通过 `IllegalArgumentException` 上报？（不由 Controller 自行 catch）
- [ ] Swagger UI 中是否能看到并成功 "Try it out"？

=== 2026.5.28 ===

## 学生创建接口变更

学生创建接口 `POST /api/students` 不再接受 `Student` 实体，改为接受 `StudentRequest`，并通过 `@Valid` 注解触发 Jakarta Validation 校验。`StudentRequest` 对 `studentNo`、`name`、`className` 三个字段均标注了 `@NotBlank` 约束，确保空值和空字符串在 Controller 层即被拦截，返回 400 错误码。新增 `spring-boot-starter-validation` 依赖以支持校验功能。

## 作品提交接口变更

作品提交接口 `POST /api/submissions` 不再接受 `WorkSubmission` 实体，改为接受 `SubmissionRequest`，并通过 `@Valid` 注解触发校验。`SubmissionRequest` 对 `studentId`（Long）使用 `@NotNull`，对 `title`、`fileName`、`workType`（String）使用 `@NotBlank`，确保必填字段在 Controller 层即被拦截。Service 层移除原有的手动 `isBlank()` 校验逻辑，由 Bean Validation 统一负责。

## 教师评价接口变更

`TeacherReviewRequest` 新增校验注解：`teacherScore`（BigDecimal）使用 `@NotNull` + `@DecimalMin("0.0")` + `@DecimalMax("100.0")` 约束分数在 0-100 范围内；`teacherComment` 使用 `@NotBlank` 确保评语不为空。Controller 层 `saveTeacherReview` 方法参数加 `@Valid` 触发校验。Service 层移除原有的 `validateScore()` 和 `isBlank()` 手动校验方法，由 Bean Validation 统一负责。

## 统一校验错误响应

`ApiExceptionHandler` 新增 `MethodArgumentNotValidException` 异常处理器。当 `@Valid` 校验失败时，返回第一个字段的错误消息（即校验注解中 `message` 的值），响应格式与业务异常一致：`{ "message": "错误原因" }`，HTTP 状态码 400。

## 成绩导出 Excel 实现

`POST /api/export/excel` 接口改为返回真正的 Excel 文件流（`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`），不再返回 JSON。新增 `com.alibaba:easyexcel:4.0.3` 依赖。`ExportRow` 使用 `@ExcelProperty` 定义导出列（学号、姓名、班级、作品标题、类型、文件名、AI 评分/问题/评语、教师评分/评语、评价状态）。`ExportService` 联合查询 student、submission、evaluation 三表，在内存中组装行数据后通过 EasyExcel 流式写出。删除占位 `ExportResponse` 类。
