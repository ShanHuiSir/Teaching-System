# 05-接口设计总体方针

## 核心原则

1. **页面和 API 分离**：页面路由（`@Controller`）与 REST API（`@RestController`）分属两类 Controller，路径体系不同。
2. **资源导向**：URL 围绕资源命名（`/students`、`/submissions`），操作由 HTTP 方法区分。
3. **Swagger 优先**：Swagger UI 是接口的权威文档，所有变更必须同步体现在注解中。

## URL 路径规范

### REST API 前缀

所有 REST 接口统一使用 `/api` 前缀，通过类级 `@RequestMapping("/api")` 实现：

```java
@RestController
@RequestMapping("/api")
public class XxxController { ... }
```

### 资源路径命名

| 规则 | 示例 |
|---|---|
| 资源名用名词复数 | `/api/students`、`/api/submissions` |
| 子资源嵌套在父资源路径下 | `/api/submissions/{submissionId}/evaluate` |
| 用短横线分隔多词 | `/api/submissions/{submissionId}/teacher-review` |
| 不用驼峰或下划线 | 禁止 `/teacherReview`、`/teacher_review` |

### HTTP 方法与路径组合

| HTTP 方法 | 路径模式 | 语义 |
|---|---|---|
| `GET` | `/api/{资源}` | 列表查询 |
| `GET` | `/api/{资源}/{id}` | 单体查询 |
| `POST` | `/api/{资源}` | 新建 |
| `POST` | `/api/{资源}/{id}/{动作}` | 资源上的操作 |
| `DELETE` | `/api/{资源}/{id}` | 删除 |

## 参数传递规范

### 路径参数（@PathVariable）

用于资源标识符（ID），类型统一使用 `Long`：

```java
@GetMapping("/submissions/{submissionId}/evaluation")
public EvaluationResult getEvaluation(@PathVariable Long submissionId) { ... }
```

### 请求体（@RequestBody）

用于 POST 的数据载体，使用专用 DTO 封装：

```java
@PostMapping("/submissions/{submissionId}/teacher-review")
public EvaluationResult saveTeacherReview(@PathVariable Long submissionId,
                                          @RequestBody TeacherReviewRequest request) { ... }
```

### 查询参数（@RequestParam）

GET 列表查询允许使用 `@RequestParam` 传递分页、搜索和过滤条件，例如 `page`、`size`、`keyword`。

页面 Controller（`@Controller`）的表单提交也允许使用 `@RequestParam`。

## HTTP 状态码规范

| 场景 | 状态码 | 注解 |
|---|---|---|
| 查询成功 | `200 OK` | 默认，无需额外注解 |
| 创建成功 | `201 Created` | `@ResponseStatus(HttpStatus.CREATED)` |
| 删除成功（无返回体） | `204 No Content` | `@ResponseStatus(HttpStatus.NO_CONTENT)` |
| 参数校验失败 | `400 Bad Request` | 全局异常处理器统一处理 |

示例：

```java
@PostMapping("/students")
@ResponseStatus(HttpStatus.CREATED)
public Student createStudent(@RequestBody Student student) { ... }

@DeleteMapping("/students/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void deleteStudent(@PathVariable Long id) { ... }
```

## 异常处理

业务层抛出 `IllegalArgumentException`，全局 `@RestControllerAdvice` 统一转换为 400 响应：

```java
@ExceptionHandler(IllegalArgumentException.class)
@ResponseStatus(HttpStatus.BAD_REQUEST)
public ErrorResponse handleIllegalArgumentException(IllegalArgumentException exception) {
    return new ErrorResponse(exception.getMessage());
}
```

无需在每个 Controller 中写 try-catch。

## 注入方式

**强制使用构造器注入**，禁止 `@Autowired` 字段注入：

```java
@RestController
@RequestMapping("/api")
public class XxxController {

    private final XxxService xxxService;

    public XxxController(XxxService xxxService) {
        this.xxxService = xxxService;
    }
}
```

## Swagger 文档规范

### Controller 类

```java
@Tag(name = "学生管理")
@RestController
@RequestMapping("/api")
public class StudentController { ... }
```

### 方法

```java
@Operation(summary = "创建学生", description = "根据学号、姓名、班级创建一名新学生。")
@PostMapping("/students")
@ResponseStatus(HttpStatus.CREATED)
public Student createStudent(@RequestBody Student student) { ... }
```

### 注意

- `summary` 简短概括，`description` 补充细节。
- `@Tag` 的 `name` 使用中文，简洁明了。
- 页面 Controller（`@Controller`）不需要 Swagger 注解。

## 返回值类型

| 场景 | 返回类型 |
|---|---|
| 查询单体 / 操作结果 | Entity 或 DTO |
| 查询列表 | `List<Entity>` 或 `List<DTO>` |
| 简单状态 | `Map<String, String>` |
| 无返回体 | `void`（配合 204） |

## 设计检查清单

新增或修改接口时，逐项确认：

- [ ] 路径是否以 `/api` 开头？
- [ ] 路径是否使用名词复数、短横线分隔？
- [ ] 资源 ID 是否通过 `@PathVariable` 传递？
- [ ] POST 数据是否封装为专用 DTO？
- [ ] 是否使用了 `@RequestParam`？（仅 GET 查询参数或页面表单允许）
- [ ] 是否使用构造器注入而非 `@Autowired`？
- [ ] 是否标注了 `@Tag` 和 `@Operation`？
- [ ] 创建/删除是否标注了正确的 HTTP 状态码？
- [ ] 异常是否通过 `IllegalArgumentException` 上报？（不由 Controller 自行 catch）
- [ ] Swagger UI 中是否能看到并成功 "Try it out"？

## 参数校验体系建立

新增 `spring-boot-starter-validation` 依赖。Controller 层通过 `@Valid` 触发 Jakarta Bean Validation，`ApiExceptionHandler` 新增 `MethodArgumentNotValidException` 处理器统一返回 `{ "message": "..." }`（400）。

## 接口 DTO 化

| 接口 | 原入参 | 新入参 | 校验规则 |
|---|---|---|---|
| `POST /api/students` | `Student` | `StudentRequest` | `studentNo`/`name`/`className`: `@NotBlank` |
| `POST /api/submissions` | `WorkSubmission` | `SubmissionRequest` | `studentId`: `@NotNull`; `title`/`fileName`/`workType`: `@NotBlank` |
| `POST /api/submissions/{id}/teacher-review` | `TeacherReviewRequest` | 同上（追加注解） | `teacherScore`: `@NotNull` + `@DecimalMin("0.0")` + `@DecimalMax("100.0")`; `teacherComment`: `@NotBlank` |

Service 层移除手动校验逻辑（`isBlank()`、`validateScore()`），由 DTO 注解统一负责。

## 成绩导出 Excel 实现

新增 `com.alibaba:easyexcel:4.0.3` 依赖。`POST /api/export/excel` 改为返回 Excel 文件流（`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`），文件名通过 RFC 5987 编码。`ExportRow` 定义 12 列导出字段，`ExportService` 联合三表查询后流式写出。删除占位 `ExportResponse`。

=== 2026.5.29 ===

## CORS 跨域配置

新增 `CorsConfig` 实现 `WebMvcConfigurer`，对 `/api/**` 路径开放跨域访问：允许所有来源（`allowedOriginPatterns("*")`）、支持 GET/POST/PUT/DELETE/OPTIONS 方法、允许所有请求头、允许携带 Cookie（`allowCredentials(true)`）。供独立前端工程调用后端接口使用。

## 全局异常处理完善

`ApiExceptionHandler` 新增两个处理器：
- `HttpMessageNotReadableException` → 400 → `{ "message": "请求体格式错误" }`（请求 JSON 格式不正确时触发）
- `Exception` → 500 → `{ "message": "服务器内部错误" }`（兜底处理未预期的运行时异常，同时打印日志）

所有错误响应统一为 `{ "message": "..." }` 格式。新增 `NoResourceFoundException` → 404 静默处理，不打印堆栈。

## 统一响应体 DTO

新增 `ApiResponse<T>` 统一响应体，结构为 `{ "code": 200, "message": "success", "data": ... }`，为后续独立前端工程统一响应格式做准备。

当前主线仍保留旧 Thymeleaf 页面作为演示兜底，页面中的 JS 仍按旧格式（直接数组/对象）解析 `/api/students`、`/api/submissions`、`/api/evaluations` 等响应。因此 `ApiResponseAdvice` 暂不自动包装所有 `@RestController` 成功响应，只对 Controller 方法显式返回 `ApiResponse` 的场景生效，避免改变现有接口响应结构。

当前生效规则：

| 条件 | 处理方式 | 原因 |
|---|---|---|
| 返回类型为 `ApiResponse` | 保持 / 返回统一响应体 | 支持新接口逐步采用统一格式 |
| 返回类型不是 `ApiResponse` | 保持原返回结构 | 兼容旧 Thymeleaf 页面和现有接口调用 |

保留的防护规则：

| 跳过条件 | 原因 |
|---|---|
| 路径以 `/v3/api-docs` 或 `/swagger-ui` 开头 | Springdoc 的 OpenAPI JSON 不能被包装 |
| `body` 已是 `ApiResponse` 实例 | 避免重复包装 |
| 返回类型为 `void` | DELETE 204 / Excel 文件流等无响应体场景 |

**注意事项**：后续当前端完全迁移到独立工程，并完成统一请求封装后，可再评估是否将所有成功响应统一包装；届时前端需统一做 `response.data` 解包。

=== 2026.5.31 ===

## 学生分页查询

新增 `GET /api/students/page`，用于学生管理页分页加载，避免 `/api/students` 一次性返回过多数据。

查询参数：

| 参数 | 说明 |
|---|---|
| `page` | 页码，从 0 开始；小于 0 时按 0 处理 |
| `size` | 每页数量；最小 1，最大 200 |
| `keyword` | 可选关键字，按学号或姓名模糊查询 |

返回体使用 `StudentPageResponse`，字段包括 `content`、`page`、`size`、`totalElements`、`totalPages`、`hasPrevious`、`hasNext`。

保留 `GET /api/students` 作为兼容接口，但后端限制最多返回前 200 条学生记录，避免无限制 `findAll()`。
