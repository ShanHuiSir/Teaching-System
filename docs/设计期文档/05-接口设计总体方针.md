# 接口设计总体方针

## 维护原则

详细接口路径、请求参数、返回值和状态码以 Swagger / OpenAPI 为准。本文档只说明接口设计的总体原则，避免 Markdown 文档和代码重复维护。

## 基本原则

- 接口统一以 `/api` 开头。
- 请求和返回数据使用 JSON。
- 控制器负责接收请求和返回结果。
- 业务判断放在 Service 层。
- 数据库访问放在 Repository 层。
- 接口说明通过 OpenAPI 注解维护。

## 路径设计

| 模块 | 示例路径 | 说明 |
| --- | --- | --- |
| 学生管理 | `/api/students` | 学生列表、新增、删除 |
| 作品提交 | `/api/submissions` | 作品提交记录 |
| AI 评价 | `/api/evaluate` | 执行 AI 评价并保存结果 |
| 教师复核 | `/api/submissions/{submissionId}/teacher-review` | 保存教师最终评价 |
| 成绩统计 | `/api/statistics/summary` | 查询统计摘要 |

## 错误响应

接口出现业务错误时返回统一错误信息：

```json
{
  "message": "错误说明"
}
```

## Swagger 使用约定

- 每个 Controller 使用 `@Tag` 标明模块。
- 每个接口使用 `@Operation` 标明用途。
- 请求和响应对象使用 `@Schema` 标明字段含义。
- 老师和队友查看详细接口时，以 Swagger 页面为准。
