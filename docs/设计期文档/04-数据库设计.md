# 04-数据库设计

## 概述

系统使用 MySQL 8.0，共三张表。当前开发期使用 H2 内存数据库，此脚本为正式环境 MySQL 建表脚本。

所有表均使用 InnoDB 引擎，字符集 utf8mb4，排序规则 utf8mb4_unicode_ci。

## E-R 关系

```
student (1) ──── (N) submission (1) ──── (1) evaluation
```

- 一个学生可以提交多份作品。
- 一份作品对应一条评价记录。
- 评价记录在 AI 评价时创建，教师评审时更新。

## 表结构

### student（学生表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | 主键 |
| `student_no` | `VARCHAR(32)` | NOT NULL, UNIQUE | 学号 |
| `name` | `VARCHAR(64)` | NOT NULL | 姓名 |
| `class_name` | `VARCHAR(64)` | NOT NULL | 班级 |

索引：
- `PRIMARY KEY (id)`
- `UNIQUE KEY uk_student_no (student_no)`

### submission（作品提交表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | 主键 |
| `student_id` | `BIGINT` | NOT NULL | 关联学生 ID |
| `student_name` | `VARCHAR(64)` | NOT NULL | 学生姓名快照 |
| `title` | `VARCHAR(128)` | NOT NULL | 作品标题 |
| `file_name` | `VARCHAR(512)` | NOT NULL | 作品文件名 |
| `file_path` | `VARCHAR(1024)` | | 服务器保存路径 |
| `file_size` | `BIGINT` | | 文件大小，单位字节 |
| `content_type` | `VARCHAR(128)` | | 文件 MIME 类型 |
| `preprocess_status` | `VARCHAR(32)` | | Py 预处理状态 |
| `preprocess_message` | `VARCHAR(512)` | | Py 预处理状态说明 |
| `preprocess_result` | `LONGTEXT` | | Py 预处理原始响应 JSON |
| `work_type` | `VARCHAR(32)` | NOT NULL | 作品类型 |
| `remark` | `TEXT` | | 备注 |
| `submitted_at` | `DATETIME` | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 提交时间 |

索引：
- `PRIMARY KEY (id)`
- `INDEX idx_student_id (student_id)`

说明：
- `student_name` 为提交时的快照，避免学生改名后历史记录丢失。
- `student_id` 当前未定义外键约束，后续正式环境可添加。
- `file_path`、`file_size`、`content_type` 在真实文件上传接口中写入；旧的元数据提交接口可为空，用于兼容演示数据。
- `preprocess_status`、`preprocess_message`、`preprocess_result` 用于记录 Java 调 Py 预处理服务的结果；Py 服务未启用时状态为 `SKIPPED`。

### evaluation（评价表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | 主键 |
| `submission_id` | `BIGINT` | NOT NULL | 关联作品提交 ID |
| `ai_score` | `DECIMAL(5,2)` | | AI 建议分数（0.00 ~ 100.00） |
| `ai_issues` | `TEXT` | | AI 发现的问题，换行分隔 |
| `ai_comment` | `TEXT` | | AI 综合评语 |
| `teacher_score` | `DECIMAL(5,2)` | | 教师最终评分（0.00 ~ 100.00） |
| `teacher_comment` | `TEXT` | | 教师最终评语 |
| `status` | `TINYINT` | NOT NULL, DEFAULT 0 | 评价状态 |

索引：
- `PRIMARY KEY (id)`
- `INDEX idx_submission_id (submission_id)`

status 状态枚举：

| 值 | 含义 |
|---|---|
| `0` | 未评价 |
| `1` | AI 已评价 |
| `2` | 教师已确认 |

说明：
- `submission_id` 当前未定义外键约束和唯一约束，实际业务中一个提交只对应一条评价记录。
- AI 相关字段在 AI 评价阶段写入，教师相关字段在教师评审阶段写入。

## 当前约束情况

三张表之间目前**未定义 FOREIGN KEY 约束**，关联关系通过应用层维护。原因：

- 开发期数据结构可能调整，外键约束会阻碍变更。
- H2 内存数据库对部分外键语法支持有限。

正式部署到 MySQL 后，建议补上：

```sql
ALTER TABLE submission ADD CONSTRAINT fk_submission_student
    FOREIGN KEY (student_id) REFERENCES student(id);

ALTER TABLE evaluation ADD CONSTRAINT fk_evaluation_submission
    FOREIGN KEY (submission_id) REFERENCES submission(id);

ALTER TABLE evaluation ADD CONSTRAINT uk_evaluation_submission
    UNIQUE (submission_id);
```

## Java 实体映射

| 表 | 实体类 | 所在包 |
|---|---|---|
| `student` | `Student.java` | `entity` |
| `submission` | `WorkSubmission.java` | `entity` |
| `evaluation` | `EvaluationResult.java` | `entity` |

实体类名与表名不完全一致，是通过 `@Table(name = "...")` 完成映射的。
