# 04-数据库设计

## 概述

系统使用 MySQL 8.0，正式数据模型当前定为六张表：

- `teaching_class`：班级表
- `student`：学生表
- `assignment`：作业表
- `submission`：作品提交表
- `submission_file`：提交文件明细表
- `evaluation`：评价表

开发期使用 H2 内存数据库，`sql/schema.sql` 保持为正式环境 MySQL 建表脚本。所有表均使用 InnoDB 引擎，字符集 utf8mb4，排序规则 utf8mb4_unicode_ci。

## E-R 关系

```
teaching_class (1) ──── (N) student
teaching_class (1) ──── (N) assignment
student        (1) ──── (N) submission
assignment     (1) ──── (N) submission
submission     (1) ──── (N) submission_file
submission     (1) ──── (1) evaluation
```

- 一个班级可以有多名学生，也可以布置多份作业。
- 一名学生可以提交多份作品。
- 一份作业可以收到多份提交。
- 一份提交至少保留主文件快照，并通过 `submission_file` 支持后续多文件扩展。
- 一份提交在业务上对应一条评价记录，评价记录在 AI 评价时创建，教师复核时更新。

## 表结构

### teaching_class（班级表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | 主键 |
| `name` | `VARCHAR(64)` | NOT NULL, UNIQUE | 班级名称 |
| `grade` | `VARCHAR(16)` | | 年级 |
| `description` | `TEXT` | | 班级说明 |
| `created_at` | `DATETIME` | NOT NULL | 创建时间 |
| `updated_at` | `DATETIME` | NOT NULL | 更新时间 |

索引：
- `PRIMARY KEY (id)`
- `UNIQUE KEY uk_teaching_class_name (name)`

说明：表名使用 `teaching_class`，避免 `class` 与 Java/SQL 保留字语义冲突；接口仍使用 `/api/classes`。

### student（学生表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | 主键 |
| `student_no` | `VARCHAR(32)` | NOT NULL, UNIQUE | 学号 |
| `name` | `VARCHAR(64)` | NOT NULL | 姓名 |
| `class_id` | `BIGINT` | | 班级 ID |
| `class_name` | `VARCHAR(64)` | NOT NULL | 班级名称快照 |

索引：
- `PRIMARY KEY (id)`
- `UNIQUE KEY uk_student_no (student_no)`
- `INDEX idx_student_class_id (class_id)`

说明：`class_id` 是正式关系字段，`class_name` 保留为快照和旧前端兼容字段。

### assignment（作业表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | 主键 |
| `title` | `VARCHAR(128)` | NOT NULL | 作业标题 |
| `description` | `TEXT` | | 作业说明 |
| `work_type` | `VARCHAR(32)` | NOT NULL | 作品类型 |
| `class_id` | `BIGINT` | | 班级 ID；为空表示跨班级作业 |
| `class_name` | `VARCHAR(64)` | | 班级名称快照 |
| `published_at` | `DATETIME` | NOT NULL | 发布时间 |
| `due_at` | `DATETIME` | | 截止时间 |
| `created_at` | `DATETIME` | NOT NULL | 创建时间 |
| `updated_at` | `DATETIME` | NOT NULL | 更新时间 |

索引：
- `PRIMARY KEY (id)`
- `INDEX idx_assignment_class_id (class_id)`
- `INDEX idx_assignment_published_at (published_at)`

说明：当前实现为“一份作业可绑定一个班级或跨班级”。若后续需要一份作业精准分发到多个班级，可增加作业-班级中间表。

### submission（作品提交表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | 主键 |
| `student_id` | `BIGINT` | NOT NULL | 学生 ID |
| `student_name` | `VARCHAR(64)` | NOT NULL | 学生姓名快照 |
| `assignment_id` | `BIGINT` | | 作业 ID |
| `assignment_title` | `VARCHAR(128)` | | 作业标题快照 |
| `title` | `VARCHAR(128)` | NOT NULL | 作品标题 |
| `file_name` | `VARCHAR(512)` | NOT NULL | 主文件名快照 |
| `file_path` | `VARCHAR(1024)` | | 主文件保存路径快照 |
| `file_size` | `BIGINT` | | 主文件大小，单位字节 |
| `content_type` | `VARCHAR(128)` | | 主文件 MIME 类型 |
| `preprocess_status` | `VARCHAR(32)` | | Py 预处理状态 |
| `preprocess_message` | `VARCHAR(512)` | | Py 预处理状态说明 |
| `preprocess_result` | `LONGTEXT` | | Py 预处理原始响应 JSON |
| `work_type` | `VARCHAR(32)` | NOT NULL | 作品类型 |
| `remark` | `TEXT` | | 备注 |
| `submitted_at` | `DATETIME` | NOT NULL | 提交时间 |
| `updated_at` | `DATETIME` | NOT NULL | 更新时间 |

索引：
- `PRIMARY KEY (id)`
- `INDEX idx_submission_student_id (student_id)`
- `INDEX idx_submission_assignment_id (assignment_id)`

说明：
- `student_name` 和 `assignment_title` 为提交时快照，避免学生或作业改名后历史记录失真。
- `file_name`、`file_path`、`file_size`、`content_type` 保留主文件快照，兼容当前前端和 AI 服务。
- `preprocess_status`、`preprocess_message`、`preprocess_result` 用于记录 Java 调 Py 预处理服务结果；Py 服务未启用时状态为 `SKIPPED`。

### submission_file（提交文件明细表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | 主键 |
| `submission_id` | `BIGINT` | NOT NULL | 提交 ID |
| `file_name` | `VARCHAR(512)` | NOT NULL | 原始文件名 |
| `file_path` | `VARCHAR(1024)` | | 服务器保存路径 |
| `file_size` | `BIGINT` | | 文件大小，单位字节 |
| `content_type` | `VARCHAR(128)` | | 文件 MIME 类型 |
| `file_role` | `VARCHAR(32)` | NOT NULL | 文件角色，当前主文件为 `PRIMARY` |
| `primary_file` | `BOOLEAN` | NOT NULL | 是否主文件 |
| `sort_order` | `INT` | NOT NULL | 同一提交内排序 |
| `created_at` | `DATETIME` | NOT NULL | 创建时间 |

索引：
- `PRIMARY KEY (id)`
- `INDEX idx_submission_file_submission_id (submission_id)`

说明：当前上传接口写入一条 `PRIMARY` 主文件记录。后续若支持多文件上传，只需继续向该表追加明细，并保持一条主文件供下载、预览和 AI 默认处理。

### evaluation（评价表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | 主键 |
| `submission_id` | `BIGINT` | NOT NULL | 关联作品提交 ID |
| `ai_score` | `DECIMAL(5,2)` | | AI 建议分数（0.00 ~ 100.00） |
| `ai_issues` | `TEXT` | | AI 发现的问题，换行分隔 |
| `ai_comment` | `TEXT` | | AI 综合评语 |
| `dimension_scores` | `TEXT` | | AI 分维度评分 JSON |
| `teacher_score` | `DECIMAL(5,2)` | | 教师最终评分（0.00 ~ 100.00） |
| `teacher_comment` | `TEXT` | | 教师最终评语 |
| `status` | `TINYINT` | NOT NULL, DEFAULT 0 | 评价状态 |

索引：
- `PRIMARY KEY (id)`
- `INDEX idx_evaluation_submission_id (submission_id)`

status 状态枚举：

| 值 | 含义 |
|---|---|
| `0` | 未评价 |
| `1` | AI 已评价 |
| `2` | 教师已确认 |

`dimension_scores` 存储格式：

```json
[{"name":"代码质量","score":88,"comment":"命名规范良好"}]
```

由流式评分和非流式评分的 `/api/evaluate/real` 写回，教师复核时保留。前端通过 `JSON.parse` 渲染维度进度条。Java 实体通过 `@JsonRawValue` 确保序列化为 JSON 数组而非转义字符串。

## 当前约束情况

六张表之间目前**未定义 FOREIGN KEY 约束**，关联关系通过应用层维护。原因：

- 开发期数据结构仍可能调整，外键约束会阻碍变更。
- H2 内存数据库对部分外键语法支持有限。
- 当前验收重点是稳定三端数据契约，先保持建表和初始化数据轻量。

正式部署到 MySQL 后，建议补上：

```sql
ALTER TABLE student ADD CONSTRAINT fk_student_class
    FOREIGN KEY (class_id) REFERENCES teaching_class(id);

ALTER TABLE assignment ADD CONSTRAINT fk_assignment_class
    FOREIGN KEY (class_id) REFERENCES teaching_class(id);

ALTER TABLE submission ADD CONSTRAINT fk_submission_student
    FOREIGN KEY (student_id) REFERENCES student(id);

ALTER TABLE submission ADD CONSTRAINT fk_submission_assignment
    FOREIGN KEY (assignment_id) REFERENCES assignment(id);

ALTER TABLE submission_file ADD CONSTRAINT fk_submission_file_submission
    FOREIGN KEY (submission_id) REFERENCES submission(id);

ALTER TABLE evaluation ADD CONSTRAINT fk_evaluation_submission
    FOREIGN KEY (submission_id) REFERENCES submission(id);

ALTER TABLE evaluation ADD CONSTRAINT uk_evaluation_submission
    UNIQUE (submission_id);
```
