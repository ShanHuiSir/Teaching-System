# 15-AI 服务设计

说明 `ai-service/` 的设计意图、Java 调用方式、Python 内部架构和当前完成度。

## Java 侧使用

### 当前模式：FakeAIService（已实现）

```
Java EvaluationService
  → AIService.evaluate(AIEvalRequest { studentName, fileName })
    → FakeAIService 返回硬编码 EvaluationResult（aiScore=82.50）
```

无需启动 Python，`mvn spring-boot:run` 即走通全流程。用于离线演示和日常开发。

### 真实 AI 模式：HttpAIService（未实现）

计划流程：

```
Java EvaluationService
  → HttpAIService.evaluate(AIEvalRequest)
    → RestTemplate POST http://127.0.0.1:8000/api/evaluate
      → Python FastAPI 返回 { aiScore, aiIssues, aiComment, status }
```

Java 侧待做的事：
1. 新建 `HttpAIService implements AIService`
2. 注入 `RestTemplate`，配置 `ai-service.base-url`
3. 调用 `POST /api/evaluate`，传 `studentName` + `fileName` 表单字段
4. 通过 `@Profile("ai-real")` 切换 `FakeAIService` / `HttpAIService`

### 真实文件上传 + 预处理（未实现）

当需要上传真实 DOCX 文件并走预处理管线时，Java 侧需调用 `POST /api/evaluate/real`：

```
multipart/form-data: file=report.docx, studentName=张三
→ Python 预处理 → 返回 content + renderStatus + aiScore(null, 留待 AI)
```

Java 侧待做的事：
1. `POST /api/submissions/upload`（队长契约草案），保存文件到磁盘
2. 新增 `HttpAIService.evaluateReal(MultipartFile)` 或类似方法
3. 调 `POST /api/evaluate/real` 传文件流

## Python 侧架构

### 服务入口

```
ai-service/
├── .env                   # 环境变量（gitignored，含 DEEPSEEK_API_KEY 等）
├── config.py              # 集中配置（自动加载 .env + 环境变量覆盖）
├── start.bat              # Windows 一键启动
├── start.sh               # Linux 一键启动
├── requirements.txt       # FastAPI + python-docx + PyMuPDF + EasyOCR + patool
├── DocxConv/              # 主服务模块（FastAPI，端口 8000）
│   └── src/docxconv/
│       ├── server.py          # 全部 HTTP 端点（预处理 + AI 评分）
│       ├── converters/        # DOCX 转换管线
│       │   ├── json.py        #   python-docx → 结构化 JSON
│       │   ├── img.py         #   LibreOffice + PyMuPDF → 逐页图片
│       │   ├── pandoc_img.py  #   Pandoc + WeasyPrint → 逐页图片
│       │   └── extract_images.py  # 提取内嵌图片
│       └── __main__.py        # CLI：python -m docxconv serve|to-json|to-images
├── Evaluator/             # AI 评分模块（独立包）
│   └── src/evaluator/
│       └── deepseek.py        # DeepSeek API 调用，参数全部来自 config.py
├── ScreenshotProc/        # OCR 模块
├── ArchiveProc/           # 压缩包解压模块
└── test/                  # 测试数据（不入仓库）
```

### 预处理管线

```
POST /api/preprocess  (file: .docx)
  │
  ├── convert_obj(docx)           → content   （python-docx 解析，不依赖外部进程，必定成功）
  ├── extract_images_metadata()   → images    （内嵌图片列表）
  └── 检测 LibreOffice
        ├── 存在 → docx_to_pdf → try render
        │     ├── 成功 → renderStatus=degraded, renderEngine=libreoffice
        │     └── 失败 → renderStatus=failed, renderEngine=libreoffice
        └── 不存在 → renderStatus=failed, renderEngine=none
```

渲染失败不阻断：`content` 来自 `python-docx`（纯内存操作），无论 LibreOffice 是否就绪都正常返回。

### renderStatus 设计决策

| 状态 | 含义 | 触发条件 |
|---|---|---|
| `ok` | 渲染质量无问题 | **当前不使用**。LibreOffice 不是 Word，排版有差异，用 `degraded` 诚实标注 |
| `degraded` | 渲染可用但非官方引擎 | LibreOffice 转 PDF 成功 |
| `failed` | 渲染不可用 | LibreOffice 不存在或转换抛出异常 |
| `none` | 未尝试渲染 | 仅做 DOCX 结构解析，跳过页面渲染 |

## MVP API 端点

当前阶段仅暴露 4 个端点。`/convert/*`、`/extract/*` 底层模块保留但暂不挂载为 HTTP 端点。

| 端点 | 方法 | 入参 | 返回 | 状态 |
|---|---|---|---|---|
| `/api/health` | GET | — | `{status, libreofficeAvailable}` | 已实现 |
| `/api/preprocess` | POST | `file` (任意) | `{fileType, originalFilename, extractedText, warnings}` | 已实现 |
| `/api/evaluate` | POST | `studentName` (query) | 硬编码评分 (82.5) | 已实现（假 AI，兼容 Java） |
| `/api/evaluate/real` | POST | `file` + `studentName` (query) | 预处理结果 + `aiScore/aiIssues/aiComment` | 已实现（真实 DeepSeek 评分） |

### `/api/preprocess` 支持的文件类型

| 类型 | 后缀 | 提取方式 | 说明 |
|---|---|---|---|
| 纯文本/代码 | .txt .cpp .java .py .md 等 30+ | 直接读取（自动检测 UTF-8/GBK/UTF-16） | — |
| DOCX | .docx | python-docx 结构解析 → 纯文本 | 附带 `structuredContent`（标题/段落/列表/表格） |
| DOC (旧版) | .doc | 尝试按 docx 解析 | 可能失败，返回 warning 建议转为 .docx |
| PDF | .pdf | PyMuPDF 提取文本 | 扫描件 PDF 无法提取，返回 warning |
| XLSX/XLS | .xlsx .xls | openpyxl 逐工作表提取 | 只读模式，提取含公式单元格的缓存值 |
| PPTX/PPT | .pptx .ppt | python-pptx 逐幻灯片提取 | 含表格内文本 |
| 图片 (OCR) | .png .jpg .jpeg .bmp .webp | EasyOCR 识别 → 按阅读顺序排列 | 识别结果可能有错字，附 warning |
| 压缩包 | .zip .tar .rar .7z | 解压后递归提取文本文件 | 仅提取可读文本文件，二进制文件跳过 |

### `/api/preprocess` 统一返回格式

```json
{
  "fileType": "docx",
  "originalFilename": "report.docx",
  "extractedText": "全文纯文本...",
  "warnings": []
}
```

注：`.docx` 额外返回 `structuredContent` 字段，保留标题层级和文档结构供后续格式审核使用。当前 AI 不使用此字段。

## 1. 配置体系建立

### `config.py` 集中配置

在 `ai-service/` 根目录新建 `config.py`，作为所有模块的唯一配置来源：

- 通过 `python-dotenv` 自动加载同级目录的 `.env` 文件
- 所有值均支持环境变量覆盖（`os.getenv` 优先级 > `.env` > 代码默认值）
- 涵盖：Server（HOST/PORT）、DeepSeek（API_KEY/MODEL/TEMPERATURE/MAX_TOKENS/SYSTEM_PROMPT）、文件类型集合（TEXT_EXTENSIONS/TOOL_EXTENSIONS）、OCR（LANGUAGES/GPU）、LibreOffice/Pandoc 路径自动发现

### `.env` 敏感信息隔离

```
ai-service/
└── .env   ← gitignored（根 .gitignore 已有 .env 规则）
```

包含：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DEEPSEEK_TEMPERATURE`、`DEEPSEEK_MAX_TOKENS`、`AI_SERVICE_HOST`、`AI_SERVICE_PORT`

## 2. DeepSeek 真实评分接入

### 架构变更

将 AI 评分逻辑从 `docxconv/evaluator.py`（已删除）迁移到独立包 `Evaluator/`：

```
Evaluator/
├── pyproject.toml              # hatchling 构建，含 [tool.hatch.build.targets.wheel]
└── src/evaluator/
    └── deepseek.py             # evaluate(text, student_name) → {aiScore, aiIssues, aiComment}
```

### `deepseek.py` 与 `config.py` 的关系

- `deepseek.py` 通过 `import config` 读取所有参数，不再硬编码
- 读取项：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DEEPSEEK_TEMPERATURE`、`DEEPSEEK_MAX_TOKENS`、`EVAL_SYSTEM_PROMPT`
- `_get_client()` 使用 `config.DEEPSEEK_API_KEY` 创建 OpenAI 客户端，全局单例延迟初始化

### `/api/evaluate/real` 行为变更

- 之前：预处理管线返回 `extractedText` + `aiScore=null`（AI 占位，未实际调用）
- 现在：`file → preprocess → evaluate_content(extractedText, studentName) → JSON`
- 失败兜底：空文本返回 aiScore=0 + 提示信息；API 异常返回 503；JSON 解析失败返回 aiScore=0 + 原始输出片段

### 评分效果（4 组实测样本）

| 样本 | 字数 | aiScore | 简评 |
|---|---|---|---|
| SimpleTest.docx（简单框架） | ~50 | 65 | 内容过于简略，列表格式混乱 |
| TableTest.docx（活动备案表） | 1596 | 72 | 活动名称与内容不符，结构混乱 |
| DifficultTest.docx（职业规划书） | 7532 | 78 | 结构完整但计划部分缺失，优劣势缺乏实例 |
| student_essay.txt（AI教育论文） | 637 | 85 | 结构清晰但深度不足，缺引言和结论 |

分数与内容质量正相关，评分逻辑合理。
