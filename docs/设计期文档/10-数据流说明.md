# 10-数据流说明

## 总体数据流

```
班级信息 (TeachingClass)
  │
  ▼
学生信息 (Student)
  │
  ▼
作业定义 (Assignment)
  │
  ▼
作品提交 (WorkSubmission + SubmissionFile)
  │
  ▼
AI 评价 (RealAIService / Python SSE / FakeAIService 降级 → EvaluationResult)
  │
  ▼
教师复核 (TeacherReviewRequest → EvaluationResult 更新)
  │
  ▼
成绩统计 (StatisticsSummaryResponse)
  │
  ▼
成绩导出 (ExportService → Excel 文件流)
```

数据库表关系：

```
teaching_class (1) ──── (N) student
teaching_class (1) ──── (N) assignment
student        (1) ──── (N) submission
assignment     (1) ──── (N) submission
submission     (1) ──── (N) submission_file
submission     (1) ──── (1) evaluation
```

### 真实文件上传流程

第 8 天新增真实文件上传接口，供前端提交作业文件并生成作品提交记录。

```text
POST /api/submissions/upload
  Content-Type: multipart/form-data
  FormData:
    studentId = 1
    assignmentId = 1
    title = "实验报告"
    workType = "实验报告"
    remark = "真实上传测试"
    file = report.docx
    │
    ▼
SubmissionController.uploadSubmission(...)
    │
    ▼
SubmissionService.createSubmissionWithFile(...)
    │
    ├─ 校验学生存在
    ├─ 校验文件非空、大小不超过 50MB、扩展名受支持
    ├─ 保存 submission 记录，生成 submissionId
    ├─ 保存原始文件到 uploads/submissions/{submissionId}/原始文件名
    ├─ 回写 filePath、fileSize、contentType
    ├─ 写入 submission_file 主文件明细
    ├─ 根据 app.preprocess.enabled 决定是否调用 Py 侧 /api/preprocess
    ├─ 记录 preprocessStatus、preprocessMessage、preprocessResult
    │
    ▼
返回 WorkSubmission，HTTP 201
```

Java 侧不解析 DOCX、不处理压缩包、不做 OCR。真实预处理由 Py 侧完成；Java 只负责通过 HTTP `multipart/form-data` 转发学生上传的原始文件和提交元数据。

Py 预处理默认关闭，避免 Py 服务未启动时影响作业上传：

```properties
app.preprocess.enabled=false
app.preprocess.endpoint-url=http://localhost:8000/api/preprocess
```

开启后 Java 发送字段：

```text
file
submissionId
studentId
title
workType
originalFilename
contentType
```

返回示例：

```json
{
  "id": 7,
  "studentId": 1,
  "studentName": "张三",
  "assignmentId": 1,
  "assignmentTitle": "实验报告",
  "title": "实验报告",
  "fileName": "report.docx",
  "filePath": "uploads/submissions/7/report.docx",
  "fileSize": 20480,
  "contentType": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
  "preprocessStatus": "SKIPPED",
  "preprocessMessage": "Py预处理未启用",
  "preprocessResult": null,
  "workType": "实验报告",
  "remark": "真实上传测试"
}
```

文件明细查询与主文件下载：

```text
GET /api/submissions/{id}/files
    │
    ▼
返回 submission_file 明细列表

GET /api/submissions/{id}/file
    │
    ▼
优先读取 submission_file 中 primaryFile=true 的文件
    │
    └─ 若无文件明细，则使用 submission.filePath 兼容历史数据
```

## 3. AI 评价 → evaluation 表

### 页面操作

教师在作业审批页（`/review`，`ReviewPage.vue`）对某次提交触发 AI 评价。

### 数据流

```
POST /api/submissions/{submissionId}/evaluate
  Body: { "studentName": "张三", "fileName": "实验报告.docx" }
    │
    ▼
EvaluationController.evaluate(@PathVariable Long submissionId, @RequestBody AIEvalRequest request)
    │
    ▼
EvaluationService.evaluate(Long submissionId, AIEvalRequest request)
    │
    ├─ SubmissionRepository.findById(submissionId)     → 校验提交存在
    ├─ AIService.evaluate(request)                      → 调用 AI 评价
    │     │
    │     ├─ RealAIService.evaluate(...)                 → 调用 Python /api/evaluate/real
    │     └─ FakeAIService.evaluate(AIEvalRequest request) → Python 不可用时降级
    │           │
    │           └─ 返回硬编码 EvaluationResult:
    │               aiScore = 82.50
    │               aiIssues = "1. 结构不够清晰...\n2. 缺少核心论点..."
    │               aiComment = "整体完成度较好..."
    │               status = 1
    │
    ├─ EvaluationRepository.findBySubmissionId(submissionId)
    │     │
    │     ├─ 存在 → UPDATE (复用已有记录)
    │     └─ 不存在 → INSERT (新建记录)
    │
    └─ EvaluationRepository.save(saved)
          │
          └─ INSERT/UPDATE evaluation SET
               submission_id = ?, ai_score = ?, ai_issues = ?, ai_comment = ?, status = 1
               │
               ▼
             返回 EvaluationResult（status = 1，AI 已评价）
```

### 关键逻辑：INSERT 还是 UPDATE？

```
EvaluationRepository.findBySubmissionId(submissionId)
    .orElseGet(EvaluationResult::new)
```

- 首次评价：库中无记录 → `new EvaluationResult()`（id = null）→ `save()` 执行 INSERT
- 重新评价：库中已有记录 → 查出的实体有 id → `save()` 执行 UPDATE

### 涉及文件

| 层          | 文件                                                  |
|------------|-----------------------------------------------------|
| Controller | `EvaluationController.java`                         |
| Service    | `EvaluationService.java`                            |
| AI 接口      | `service/AIService.java`                            |
| AI 实现      | `service/impl/FakeAIService.java`                   |
| Repository | `EvaluationRepository.java`                         |
| Entity     | `entity/EvaluationResult.java`（映射 `evaluation` 表） |
| 入参 DTO     | `dto/AIEvalRequest.java`                            |

## 4. 教师复核 → evaluation 表更新

### 页面操作

教师在作业审批页（`/review`，`ReviewPage.vue`）参考 AI 结果后，填写教师分数和评语。

### 数据流

```
POST /api/submissions/{submissionId}/teacher-review
  Body: { "teacherScore": 88.00, "teacherComment": "整体完成较好，建议继续完善代码注释。" }
    │
    ▼
EvaluationController.saveTeacherReview(@PathVariable Long submissionId, @RequestBody TeacherReviewRequest request)
    │
    ▼
EvaluationService.saveTeacherReview(Long submissionId, TeacherReviewRequest request)
    │
    ├─ 校验：已存在 AI 评价，否则抛 "请先完成 AI 评价"
    ├─ DTO 校验：teacherScore 不为空且 0~100
    ├─ DTO 校验：teacherComment 不为空
    │
    ├─ evaluation.setTeacherScore(request.getTeacherScore())
    ├─ evaluation.setTeacherComment(request.getTeacherComment())
    ├─ evaluation.setStatus(2)   ← 教师已确认
    │
    └─ EvaluationRepository.save(evaluation)
          │
          └─ UPDATE evaluation SET teacher_score = ?, teacher_comment = ?, status = 2 WHERE id = ?
              │
              ▼
            返回 EvaluationResult（status = 2，教师已确认）
```

## 7. Python AI 评价服务（ai-service）

### 架构变更

Flask `app.py` 已废弃，全部端点合并到 DocxConv 的 FastAPI 单进程（端口 8000）。

```
Java (EvaluationService)
  │
  ├─ RealAIService           ← 真实 AI（配置开启时优先尝试）
  │
  └─ FakeAIService           ← Python 不可用或无真实文件时降级
        │  POST /api/evaluate/real  (multipart/form-data)
        ▼
   FastAPI ai-service (:8000)
        │
        ├─ POST /api/preprocess
        ├─ POST /api/evaluate/real
        └─ POST /api/evaluate/stream
        │
        ├── python-docx 解析 DOCX → 结构化 JSON（content）
        ├── LibreOffice + PyMuPDF 渲染 → 逐页图片
        ├── DeepSeek / LLM 评分
        └── 返回 aiScore / aiIssues / aiComment / dimensionScores
```

### 预处理数据流

```
POST /api/preprocess  (file: .docx)
  │
  ├── convert_obj(docx)         → content (标题/段落/列表/表格，始终返回)
  ├── extract_images_metadata() → images (内嵌图片元数据)
  ├── 检测 LibreOffice 是否就绪
  │   ├── 就绪 → docx_to_pdf → 成功 → renderStatus=degraded
  │   │                                └── 失败 → renderStatus=failed
  │   └── 缺失 → renderStatus=failed, renderEngine=none
  │
  └── 返回 { fileType, content, images, renderStatus, renderEngine, renderWarnings }
```

### renderStatus 判定

| 场景 | renderStatus | renderEngine | renderWarnings |
|---|---|---|---|
| LibreOffice 渲染成功 | `degraded` | `libreoffice` | 排版差异警告 |
| LibreOffice 不存在 | `failed` | `none` | 未检测到 LibreOffice |
| LibreOffice 渲染失败 | `failed` | `libreoffice` | 排版差异 + 渲染失败 |

**关键约束**：渲染失败不阻断 `content` 返回。`convert_obj`（python-docx）只在内存解析 XML，不依赖任何外部进程，只要文件是合法 DOCX 就必定成功。


## 异常处理

所有 Service 层抛出的 `IllegalArgumentException` 由 `ApiExceptionHandler` 统一拦截：

```
IllegalArgumentException → 400 Bad Request → { "message": "错误原因" }
```

| 触发场景          | 异常消息                 |
|---------------|----------------------|
| 评价时提交不存在      | "作品提交不存在"            |
| 教师复核前未做 AI 评价 | "请先完成 AI 评价"         |
| 教师分数为空        | "教师分数不能为空"           |
| 教师分数低于 0      | "教师分数不能低于0"          |
| 教师分数高于 100    | "教师分数不能超过100"        |
| 教师评语为空        | "教师评语不能为空"           |
| 查询不存在的评价      | "评价结果不存在"            |
