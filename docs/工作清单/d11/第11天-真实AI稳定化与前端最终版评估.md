# 第 11 天 - 真实 AI 稳定化与前端最终版评估

第 11 天目标是把第 10 天 MVP 收口后的两个关键尾巴处理清楚：

1. 真实 AI 能力从“具备接口和 Mock 测试”推进到“线上真实评分已验证”。

## B 同学反馈汇总

### 已完成或可复用内容

- 前端 build 可通过，说明 Vue 3 工程基础没有编译阻塞。
- 上传页、评价页、未审批、AI 已审批、已完成和导出页已具备 MVP 演示所需状态展示。
- #73 中有一些局部体验改动值得保留为候选，例如评价页步骤化展示、学生列表新增/删除入口、全局通知抽象和部分卡片宽度统一。

### 风险反馈

- #73 基于已关闭的 #72 继续推进，并已合入远端 `main`。
- #73 涉及登录、Cookie 认证、班级选择、班级管理、页面迁移和全局通知，范围超过第 11 天稳定化目标。
- 新增的登录和班级页面依赖尚未配套的后端能力，例如 `/user/classes`、`/class/:id/detail` 或完整班级上下文。
- Cookie 认证会改变当前固定教师账号和演示登录口径，可能影响第 10 天已验收的稳定流程。
- 一次性迁移多页样式和交互会增加回归面，尤其是状态页、评价页、上传页和导出页。

## C 同学反馈汇总

### 已完成或可确认内容

- Py 侧 AI 服务入口已统一到 FastAPI 服务。
- `/api/health`、`/api/preprocess` 和 `/api/evaluate/real` 路径口径已经明确。
- 本地路径使用 `http://localhost:8000/api/**`，线上路径通过网关前缀使用 `https://redtree.miprota.cc/ai/api/**`。
- `/api/evaluate/real` 真实评分已返回 `aiScore/aiIssues/aiComment`，第 10 天“真实 Key 未最终验收”的风险已在第 11 天补齐。

### 仍需保留的风险说明

- 真实 AI 依赖外部 Key、网络和模型服务，最终演示不应强制依赖它。
- Java 默认配置仍建议保持 `app.ai.real.enabled=false`，演示时使用 FakeAI 保底；需要展示真实 AI 时再临时开启。
- LibreOffice 缺失时 DOCX 版式渲染仍可能返回 `renderStatus=failed`，但文本提取和 AI 评分主流程不受影响。
- OCR 中文质量仍是后续增强项，不作为 MVP 阻塞条件。

## #73 前端重构评估

### PR 状态

- #72：前置尝试，已关闭未合并。
- #73：基于 #72 的后续前端重构 PR，已合并到远端 `main`。
- 当前第 11 天文档评估基线仍是 `codex/d11-final-stabilization`，本分支尚未包含 #73。
- 第 12 天必须先确认最终演示基线：继续使用当前稳定分支，还是切到含 #73 的 `main` 并补回归验证。
- 改动规模：17 个前端文件，约 1466 行新增、143 行删除。
- 主要内容：新增 LoginPage、ClassManagementPage、ClassSelectionPage、Cookie 工具、全局 notice store、SmartLogoutButton，并迁移多处业务页面样式和交互。

### 不建议直接作为最终基线的原因

| 风险 | 说明 | 结论 |
| --- | --- | --- |
| 业务范围扩大 | 登录、班级选择、班级管理都超出第 11 天稳定化目标 | 需回归确认 |
| 后端接口未配套 | 班级相关页面需要新的接口和权限上下文 | 暂不作为最终演示入口 |
| 认证口径变化 | localStorage 到 Cookie 的变化会影响当前演示登录和退出逻辑 | 暂缓 |
| 回归面过大 | 多页同时迁移，容易破坏已验收状态页和评价链路 | 暂缓 |
| 第 10 天基线已稳定 | MVP 已经可演示，应优先保护稳定版本 | 先保留稳定分支 |

### 最终版可保留候选内容

这些内容可以在第 12 天从 #73 中按“小块 + 单项验收”方式择优保留：

| 候选内容 | 可合条件 | 优先级 |
| --- | --- | --- |
| 评价页步骤化展示 | 不改 API、不改路由、不引入班级或登录依赖；AI 评价、教师复核回归通过 | P1 |
| 学生列表新增/删除按钮体验 | 只复用已有 `/api/students` 和 `/api/dev/reset-demo-data`；确认 prod 环境不暴露开发重置入口 | P1 |
| 全局通知 store | 先替换一两个页面，证明不会造成重复提示或消息丢失 | P2 |
| 卡片宽度和局部样式统一 | 只处理明显错位和移动端溢出，不做全站视觉重构 | P2 |
| 退出确认细化 | 保持当前固定教师账号演示口径，不切 Cookie 认证 | P2 |

### 暂不纳入最终演示内容

| 内容 | 暂缓原因 |
| --- | --- |
| LoginPage 整体替换 | 完整认证权限未进入 MVP，Cookie 迁移会改变演示口径 |
| ClassSelectionPage | 缺少真实班级上下文和 `/user/classes` |
| ClassManagementPage | 缺少独立班级管理后端接口和权限校验 |
| Cookie 认证体系 | 需要和后端登录、会话、权限一起设计 |
| 全页面一次性迁移 | 回归面过大，不适合第 11 天最终稳定化 |

## 当前最终版判断

第 11 天最终版建议采用以下口径：

```text
稳定主线 = 第 10 天 MVP 收口基线 + 第 11 天真实 AI 验收文档
前端最终版 = 先确认是否采用含 #73 的 main；未完成回归前不直接认定 #73 为最终稳定版
真实 AI = 能力已验证，可配置开启；演示默认保留 FakeAI 降级
```

由于 #73 已合入远端 `main`，第 12 天第一步应重新确认稳定基线。若采用 `main`，需要对 #73 涉及的登录、班级、状态页、评价页和导出页补完整回归；若继续保护第 10 天稳定 MVP，则从当前分支或第 10 天稳定提交开最终收口分支。
