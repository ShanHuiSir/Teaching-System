# 第 3 天实现阶段队长工作包

## 今日定位

第 3 天可以从 HTML 原型确认进入实现阶段，但目标不是一次性完成全部功能，而是先跑通最小可运行主流程。

今日核心主线：

```text
教师登录 -> 学生管理 -> 作品提交 -> AI 评价 -> 教师复核 -> 成绩统计/导出入口
```

队长今日职责是先把项目边界、接口字段、文件范围和验收标准铺好，再协调 B、C 同学分模块实现。

## 队长先做的 5 件事

| 顺序 | 任务 | 具体动作 | 交付物 |
| --- | --- | --- | --- |
| 1 | 锁定今日范围 | 明确今天只做最小可运行主流程，暂不做真实文件上传、真实 AI、真实 Excel 导出 | 今日范围说明 |
| 2 | 对齐页面流程 | 统一页面入口和跳转关系，避免队友各做各的页面 | 页面流程表 |
| 3 | 对齐接口字段 | 明确前端调用哪些接口、提交哪些 JSON 字段 | 接口字段表 |
| 4 | 分配文件范围 | 指定 B、C 分别改哪些页面和脚本，减少冲突 | 分工任务表 |
| 5 | 组织验收整合 | 收代码后按主流程跑一遍，记录问题和未完成项 | 验收记录 |

```text
登录 -> 学生管理 -> 作品提交 -> 进入评价 -> 执行 AI 评价 -> 保存教师最终评价
```

## 接口与字段对齐表

| 模块 | 方法 | 接口 | 前端提交/接收重点字段 | 说明 |
| --- | --- | --- | --- | --- |
| 学生列表 | GET | `/api/students` | `id`, `studentNo`, `name`, `className` | 学生管理页和作品提交页都要用 |
| 新增学生 | POST | `/api/students` | `studentNo`, `name`, `className` | B 同学实现表单时按这些字段传 |
| 删除学生 | DELETE | `/api/students/{id}` | `id` | 可作为扩展功能，非今日必须 |
| 作品列表 | GET | `/api/submissions` | `id`, `studentId`, `studentName`, `title`, `fileName`, `workType`, `remark`, `submittedAt` | 作品提交页加载列表 |
| 新增作品 | POST | `/api/submissions` | `studentId`, `title`, `fileName`, `workType`, `remark` | 先保存文件名，不做真实上传 |
| AI 评价 | POST | `/api/evaluate` | `submissionId`, `studentName`, `fileName` | C 同学在评价页调用 |
| 查询评价结果 | GET | `/api/submissions/{submissionId}/evaluation` | `aiScore`, `aiIssues`, `aiComment`, `teacherScore`, `teacherComment`, `status` | 用于回显 AI 和教师评价 |
| 保存教师复核 | POST | `/api/submissions/{submissionId}/teacher-review` | `teacherScore`, `teacherComment` | 教师确认最终成绩 |
| 统计摘要 | GET | `/api/statistics/summary` | `studentCount`, `submissionCount`, `aiEvaluatedCount`, `teacherConfirmedCount`, `averageTeacherScore` | 可放到导出页或统计区域 |
