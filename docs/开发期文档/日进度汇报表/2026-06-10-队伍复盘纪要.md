## 暴露的问题

### 1. PR 粒度仍然偏大

#85 同时包含文件预览、路由懒加载、独立预览页面，以及多个旧业务页面。结果是核心功能可用，但夹带内容破坏构建。

后续要求：

- 一个 PR 只解决一个明确任务。
- 新页面必须先说明当前路由口径。
- 新依赖必须写入 `package.json` 并通过 build。
- 不要把旧口径页面混进新版工作台主线。

### 2. 环境变量传递方式不够安全

AI Key 今天通过聊天明文传递。虽然没有提交进 Git，但从安全角度看，这仍然不是理想方式。

后续要求：

- API Key 只写入本地 `.env`。
- 文档只写变量名，不写真实值。
- 演示结束后轮换 Key。

### 3. 跨电脑联调前置条件需要提前确认

今天跨电脑联调暴露出几个前置条件：

- AI 服务必须监听 `0.0.0.0`，不能只监听 `127.0.0.1`。
- Windows 防火墙需要放行端口 `8000`。
- 两台电脑必须在同一网络下互通。
- Nushell 命令和 bash/zsh 有差异，启动命令要单独写。

这类问题以后要在正式联调前先做 health 探测，不要等到功能验收时才处理。
