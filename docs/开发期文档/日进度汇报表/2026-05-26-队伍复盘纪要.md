## 当前发现的问题

### 1. HTML 原型还没有进入仓库

目前本地还没有看到 `prototype/` 目录。

B 同学后续需要提交静态 HTML 原型，建议目录如下：

```text
prototype/
├── login.html
├── index.html
├── students.html
├── works.html
├── evaluation.html
├── statistics.html
├── export.html
└── style.css
```

原型要求：

- 页面之间能跳转。
- 风格统一。
- 数据可以写死。
- 先不接后端接口。
- 不做真实文件上传。
- 不做真实 Excel 导出。

### 2. 部分 PR 内容混杂

今天检查到有 PR 同时包含日进度、项目概述、问题记录和任务清单。这样的 PR 不方便合并，也容易覆盖已有文档。

后续建议：

| 内容 | 建议 PR 范围 |
| --- | --- |
| 日进度 | 只改 `docs/开发期文档/日进度汇报表/` |
| 设计期文档 | 只改 `docs/设计期文档/` |
| HTML 原型 | 只改 `prototype/` |
| 后端功能 | 只改 `src/`、`sql/` 和必要文档 |

### 3. 命名规范还需要继续统一

后续需要在命名规范中明确：

- 接口请求对象使用 `Request` 后缀。
- 接口响应对象使用 `Response` 后缀。
- 数据库实体不加 `DTO` 后缀。
- `DTO` 只用于既不是请求也不是响应的内部跨层传输对象。

例如：

```text
TeacherReviewRequest
StatisticsSummaryResponse
Student
WorkSubmission
```
