## 二、设计体系：从零散的 CSS 到 B 端 MD3 设计系统

### 2.1 问题诊断（改动前）

改动前的前端存在以下问题：

- **无 JavaScript**：所有按钮（新增学生、AI 评价、保存评价、导出 Excel）均为无功能静态元素
- **数据全硬编码**：学生列表、评价结果直接写在 HTML 中，未对接后端 API
- **Thymeleaf 绑定几乎未使用**：除登录错误提示外，模板无任何动态数据渲染
- **导航栏重复定义**：3 个页面各自复制相同导航代码，无模板复用
- **CSS 仅 168 行**：仅提供基础全局样式，无组件化设计，无交互态处理

### 2.2 解决方案：MD3 设计令牌体系

构建了完整的 Material Design 3 设计令牌系统，覆盖六大维度：

| 维度 | 令牌数量 | 示例 |
|------|---------|------|
| **Color** | 24 个 | Primary / Secondary / Tertiary / Error / Surface 全色阶 |
| **Elevation** | 3 级 | elevation-1（卡片浮起）→ elevation-3（对话框阴影） |
| **Shape** | 6 级 | xs(4px) → xl(24px) → full(9999px 按钮胶囊) |
| **Motion** | 5 个 | duration-short(150ms) → long(400ms)，easing-standard / emphasized |
| **Typography** | 13 级 | headline-large(32px) → label-small(11px)，统一中文字体栈 |
| **Spacing** | 8 级 | space-1(4px) → space-12(48px) |

### 2.3 组件化架构

基于令牌构建了 15 个统一组件模块：

```
.md-topbar        → 顶部导航栏（sticky 56px，品牌图标 + 导航链接 + 退出按钮）
.md-page          → 页面容器（max-w 1080px，响应式边距）
.md-page-header   → 页面头部（标题 + 操作按钮分离）
.md-card          → 卡片（header/body 分区，边框分割线）
.md-btn           → 按钮（5 种层级 × 3 种尺寸 = 15 种组合）
.md-field         → 文本字段（label + input 绑定，hover/focus/readonly 态）
.md-table         → 表格（表头底色 + hover 行高亮）
.md-chip          → 标签（班级/状态信息）
.md-toolbar       → 工具栏（搜索 + 筛选）
.md-step          → 步骤标记（①②③ 圆标数字）
.md-score         → 评分展示（56px 粗体数字 + 单位）
.md-info-grid     → 信息网格（label/value 键值对）
.md-dialog        → 对话框（遮罩层 + 卡片 + 动画 + ESC 关闭）
.md-empty         → 空状态（图标 + 引导文案）
.md-divider       → 分割线
```

### 3.2 学生管理页

| 改动点 | 改动前 | 改动后 |
|--------|--------|--------|
| 页面布局 | 无头部工具栏 | 标题 + 操作按钮分离的 page-header |

### 3.3 作品评价页（答辩演示重点）

改动前为三个平铺 panel，无层次区分。改动后采用 **三步工作流** 设计：

```
┌─ Step ① 学生与作品信息 ──────────────────────────────┐
│  info-grid: 姓名 / 学号 / 班级 / 作品文件             │
│  [执行 AI 评价]                                       │
└──────────────────────────────────────────────────────┘
┌─ Step ② AI 评价结果 ─────────────────────────────────┐
│  85 / 100 分  (56px 大号评分数字)                     │
│  ┌── 发现的问题 ──┐  ┌── 综合评语 ──┐                │
│  │ 1. 结构不清晰  │  │ 文字描述...  │                │
│  │ 2. 缺少论据    │  │              │                │
│  │ 3. 格式不规范  │  │              │                │
│  └───────────────┘   └─────────────┘                  │
└──────────────────────────────────────────────────────┘
┌─ Step ③ 教师复核 ────────────────────────────────────┐
│  最终分数 [85]                                        │
│  最终评语 [整体完成度较好，继续优化细节。]              │
│  [保存最终评价]  (44px 大按钮)                         │
└──────────────────────────────────────────────────────┘
```

关键设计决策：
- **步骤标记**：蓝色圆形数字（①②③）置于卡片 header，视觉引导评审流程
- **评分突出**：56px / 700 字重的蓝色数字，答辩投影时评委可清晰看到
- **双栏布局**：问题列表与综合评语并排，信息密度高且易浏览
- **卡片嵌套**：AI 结果内部使用浅灰背景子卡片，与教师可编辑区域形成视觉区分

## 六、后续建议

1. **JavaScript 交互层**：当前按钮仍为静态元素（"新增学生"、"执行 AI 评价"等无实际功能），需对接后端 API
2. **Thymeleaf 动态渲染**：将硬编码数据替换为 `th:each` / `th:text` 等动态绑定
3. **导航栏模板复用**：使用 `th:fragment` 提取公共导航为 Thymeleaf layout
4. **暗色模式**：MD3 令牌已有 surface 色阶体系，可通过 `prefers-color-scheme` 媒询扩展
