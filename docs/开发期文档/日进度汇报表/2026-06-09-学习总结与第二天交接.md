# 2026-06-09 学习总结与第二天交接

## 1. 今天学到了什么

今天最重要的收获是：项目验收不能只看“代码里有没有接口”，要区分清楚三类证据。

| 证据类型 | 能说明什么 | 不能说明什么 |
|---|---|---|
| Git 提交 | 代码或文档已经进入仓库 | 服务是否正在运行、接口是否已实际调用成功 |
| Swagger 页面 | API 定义和路由存在 | 真实请求一定成功、AI 模型一定可用 |
| curl / Try it out 输出 | 当前环境下接口实际返回结果 | 代码是否已经合入主线 |

因此，判断任务是否完成时，要同时看：

1. 代码是否在 `main`。
2. 服务是否启动。
3. 是否有实际调用结果。
4. 结果是否满足验收字段。

## 2. 三端服务的理解

当前项目不是一个单独网址，而是三端协同。

| 端 | 端口 | 用途 | 验收方式 |
|---|---|---|---|
| Vue 前端 | `5173` 或 Vite 实际提示端口 | 教师工作台页面 | 浏览器访问 `/dashboard`、`/classes`、`/assignments`、`/review` |
| Java 后端 | `8080` | 学生、班级、作业、提交、评价、导出等业务接口 | `curl http://127.0.0.1:8080/api/health` |
| Python AI | `8000` | 文件预处理、真实 AI 评分、SSE 流式评分 | `curl http://127.0.0.1:8000/api/health` 和 AI 接口样例 |

如果某个网址打不开，优先检查：

- 当前终端是否在正确项目目录。
- 对应端口是否有服务监听。
- Vite 是否自动换了端口。
- 打开的地址是不是对应的服务端口。

## 4. 今天对 B / C 任务的判断方式

### B 同学

B 的任务重点是 `/review` 文件交互：

| 任务 | 完成判断 |
|---|---|
| 下载按钮 | 点击后能调用 `GET /api/submissions/{id}/file` 并下载文件 |
| 预览按钮 | 文本/代码类文件能预览，不支持预览时给下载提示 |
| 文件信息去硬编码 | 不再写死 `100 KB`，优先使用真实文件元数据 |
| 导出状态 | `/assignments` 导出有 loading、防重复点击、成功/失败提示 |
